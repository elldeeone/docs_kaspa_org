This guide walks you through getting a Kaspa node fully operational and querying it using the built-in RPC interface. It assumes you have already completed the [Installation](/docs/getting-started/installation) steps.

## Start the Node

Launch `kaspad` with the UTXO index enabled:

```bash
./target/release/kaspad --utxoindex
```

The node will begin connecting to peers on the Kaspa mainnet (default port `16111`) and start synchronizing the BlockDAG. The wRPC server listens on `127.0.0.1:17110` by default (gRPC is on port `16110`).

<Callout type="info">
If you want the wRPC server to be accessible from other machines on your network, start with `--rpclisten 0.0.0.0:17110`. Be cautious exposing RPC to untrusted networks.
</Callout>

## Check Node Status with the Wallet CLI

The `kaspa-wallet` CLI tool can connect to your local node's RPC server. You can use it to check connectivity and node information.

Open a second terminal and run:

```bash
./target/release/kaspa-wallet
```

This opens the interactive wallet CLI. You can also use the `kaspa-wrpc-client` or make direct JSON-RPC calls.

## Querying RPC Directly

Kaspa's RPC interface uses the wRPC protocol (WebSocket-based RPC). You can interact with it programmatically or via command-line tools.

### Using the RPC with curl (JSON-RPC over WebSocket)

For quick checks, you can use tools like `websocat` to issue RPC calls:

```bash
# Install websocat
cargo install websocat

# Query the node info
echo '{"id":1,"method":"getInfoRequest","params":{}}' | websocat ws://127.0.0.1:17110
```

This returns a JSON response with node information including the current network, number of connected peers, and whether the node is synced.

### Common RPC Methods

Here are the most frequently used RPC methods for checking node status:

#### Get Node Info

```bash
echo '{"id":1,"method":"getInfoRequest","params":{}}' | websocat ws://127.0.0.1:17110
```

Example response:

```json
{
  "id": 1,
  "method": "getInfoResponse",
  "params": {
    "p2pId": "abc123...",
    "serverVersion": "0.15.0",
    "isSynced": true,
    "isUtxoIndexed": true,
    "mempoolSize": 12,
    "networkName": "kaspa-mainnet"
  }
}
```

<Callout type="info">
The `isSynced` field tells you whether your node has fully caught up with the network. Wait for this to be `true` before relying on the node for wallet operations or mining.
</Callout>

#### Get Block DAG Info

```bash
echo '{"id":1,"method":"getBlockDagInfoRequest","params":{}}' | websocat ws://127.0.0.1:17110
```

This returns the current state of the BlockDAG including:

- **`blockCount`** -- Total number of blocks in the DAG
- **`headerCount`** -- Total number of headers received
- **`virtualDaaScore`** -- The current DAA (Difficulty Adjustment Algorithm) score, which serves as a monotonic block-time proxy
- **`pruningPointHash`** -- The hash of the current pruning point

#### Get Connected Peer Info

```bash
echo '{"id":1,"method":"getConnectedPeerInfoRequest","params":{}}' | websocat ws://127.0.0.1:17110
```

This lists all currently connected peers along with their addresses, protocol versions, and sync status.

## Monitoring Sync Progress

During initial sync, you can monitor progress by periodically querying `getBlockDagInfoRequest` and watching the `virtualDaaScore` increase toward the current network DAA score. You can compare your node's DAA score against a public Kaspa block explorer such as [kas.fyi](https://kas.fyi) to estimate how far along the sync is.

A rough indication of sync progress:

```bash
# Run this in a loop to watch sync progress
while true; do
  echo '{"id":1,"method":"getBlockDagInfoRequest","params":{}}' | websocat ws://127.0.0.1:17110 2>/dev/null | python3 -c "
import sys, json
data = json.load(sys.stdin)
score = data['params']['virtualDaaScore']
print(f'DAA Score: {score}')
"
  sleep 10
done
```

<Callout type="warn">
Initial synchronization can take anywhere from a few hours to over a day depending on your hardware and network connection. The node must download, validate, and index the entire BlockDAG history. An SSD is strongly recommended.
</Callout>

## Connecting to Testnet

To experiment without using real KAS, you can connect to the Kaspa testnet:

```bash
./target/release/kaspad --utxoindex --testnet
```

The testnet wRPC server runs on port `17210` by default. All RPC queries work the same way -- just adjust the port:

```bash
echo '{"id":1,"method":"getInfoRequest","params":{}}' | websocat ws://127.0.0.1:17210
```

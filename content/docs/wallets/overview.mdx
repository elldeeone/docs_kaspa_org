## Overview

The Kaspa ecosystem offers several wallet options, each suited to different use cases. All Kaspa wallets use the same HD derivation standard (BIP-32/39/44), which means your 24-word seed phrase is portable — you can recover your funds in any compatible wallet.

This page helps you choose the right wallet for your needs and understand the trade-offs between security, convenience, and functionality.

## Wallet Types

### Web Wallet

The [Kaspa Web Wallet](https://wallet.kaspa.org) runs entirely in your browser. Your keys are generated and stored locally in browser storage — they never leave your device. The web wallet is the easiest way to get started with Kaspa and is suitable for everyday use.

### CLI Wallet

The [CLI Wallet](/docs/wallets/cli-wallet) (`kaspa-cli-wallet`) is a command-line tool included in the rusty-kaspa project. It connects to a Kaspa node via wRPC and performs all key management and signing locally. The CLI wallet is ideal for server environments, scripting, and advanced operations like multi-sig and UTXO sweeps.

### Browser Extension (KasVault)

KasVault is a browser extension wallet similar to MetaMask. It integrates with web-based Kaspa dApps, allowing you to approve transactions and sign messages directly from your browser. KasVault can also interface with Ledger hardware wallets for hardware-backed signing.

### Hardware Wallets

[Hardware wallets](/docs/wallets/hardware-wallets) store your private keys on a dedicated physical device with a secure element. Kaspa is supported on Ledger (Nano S Plus, Nano X) and Tangem NFC cards. Hardware wallets are the recommended option for securing large amounts of KAS.

### Mobile Wallets

Mobile wallets are available for iOS and Android, including the Tangem app and community-developed wallets. These are convenient for on-the-go transactions and point-of-sale payments.

## Recommendations by Use Case

### Daily Spending and Receiving

Use the **Web Wallet** or **KasVault** browser extension. Both provide a straightforward interface for sending and receiving KAS. The web wallet requires no installation beyond visiting a URL, while KasVault integrates with dApps.

### Large Holdings and Long-Term Storage

Use a **hardware wallet** (Ledger or Tangem). Your private keys remain on the physical device and are never exposed to your computer. Even if your machine is compromised, an attacker cannot extract your keys.

<Callout>
For significant holdings, a hardware wallet is strongly recommended. Software wallets — even well-designed ones — are only as secure as the device they run on.
</Callout>

### Developers and Server Environments

Use the **CLI Wallet**. It supports scripting, automation, and advanced features like multi-sig, UTXO sweeps, and watch-only mode. It is the best choice for managing mining payouts, running payment infrastructure, or integrating Kaspa into backend systems.

### dApp Interaction

Use **KasVault**. It functions like MetaMask for the Kaspa ecosystem, providing a popup-based approval flow for web applications that request transaction signatures.

## Seed Phrase Portability

All standard Kaspa wallets derive keys using the same BIP-44 derivation path (`m/44'/111111'/0'/0/index`). This means:

- A wallet created in the web wallet can be recovered in the CLI wallet using the same 24-word seed phrase.
- A wallet created in KasVault can be recovered on a Ledger device (if the same mnemonic is used).
- You can freely move between wallets without losing access to your funds.

<Callout type="info">
Tangem cards are an exception — they use a multi-card backup system instead of a seed phrase. Tangem wallets cannot be recovered using a mnemonic in other wallet software.
</Callout>

## Choosing a Wallet: Quick Guide

- **New to Kaspa?** Start with the [Web Wallet](/docs/wallets/web-wallet).
- **Holding more than you can afford to lose?** Get a [hardware wallet](/docs/wallets/hardware-wallets).
- **Building applications or running infrastructure?** Use the [CLI Wallet](/docs/wallets/cli-wallet).
- **Interacting with dApps?** Install KasVault.

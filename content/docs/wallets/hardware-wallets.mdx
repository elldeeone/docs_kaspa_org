## Why Use a Hardware Wallet?

A hardware wallet keeps private keys on a dedicated device instead of on your desktop/browser runtime. This reduces exposure to malware, clipboard hijacking, and remote compromise of your primary machine.

<Callout>
Hardware-wallet compatibility and app support change over time. Always verify current Kaspa support directly with the device vendor and companion wallet before funding an address.
</Callout>

## Compatibility Checklist

Before selecting a device/app combination:

1. Confirm Kaspa network/account support in the vendor's current compatibility docs.
2. Confirm the companion app can derive and display Kaspa receive addresses.
3. Send/receive a small test amount before moving production funds.
4. Confirm backup/recovery steps end-to-end on a spare environment.

## Companion App Model

Most hardware wallets use a companion app for:

- Address discovery and balance display.
- Transaction construction.
- Requesting signatures from the hardware device.

The private key operation should happen on the hardware device, with explicit on-device approval for transaction signing.

## Signing Flow (General)

1. Build an unsigned transaction in the companion app.
2. Send signing request to the hardware device.
3. Verify destination and amount on the device display (or trusted device workflow).
4. Approve signing on-device.
5. Broadcast from the companion app.

## Recovery and Backups

Hardware wallets do not all use the same recovery model:

- Some use mnemonic-based recovery.
- Some use vendor-specific card/device backup schemes.

Use only the vendor's official recovery instructions, and test recovery before storing large balances.

## Security Best Practices

- Buy devices directly from the vendor or authorized channels.
- Initialize the device yourself; never trust pre-initialized seed material.
- Keep firmware and companion apps updated.
- Store backups in separate secure physical locations.
- Use a dedicated machine/profile for large-value operations.

## The Kaspa SDK Ecosystem

Kaspa provides a layered SDK ecosystem rooted in the [rusty-kaspa](https://github.com/kaspanet/rusty-kaspa) Rust implementation. The Rust crates form the canonical source of truth for all consensus logic, wallet operations, and RPC communication. Higher-level SDKs compile or bind to these crates, ensuring consistent behavior across languages and platforms.

```
┌─────────────────────────────────────────────────────┐
│                  Applications                       │
├──────────┬──────────┬──────────┬────────────────────┤
│  WASM    │  Python  │  Rust    │  Community SDKs    │
│  SDK     │  SDK     │  Crates  │  (Go, C#, etc.)    │
├──────────┴──────────┴──────────┴────────────────────┤
│              wRPC / gRPC Transport                   │
├─────────────────────────────────────────────────────┤
│              Kaspa Node (rusty-kaspa)                │
└─────────────────────────────────────────────────────┘
```

All SDKs communicate with the Kaspa network through a running node using either **wRPC** (WebSocket-based RPC, the default for most applications) or **gRPC** (used by infrastructure operators and some community tools). The SDKs themselves do not participate in consensus or block production; they are clients that construct transactions, query state, and subscribe to events.

## Choosing an SDK

The right SDK depends on your target platform, performance requirements, and development workflow. Use the decision matrix below as a starting point.

| Use Case | Recommended SDK | Why |
|---|---|---|
| Browser wallet or DApp | [WASM SDK](/docs/sdks/wasm-sdk) | Runs in the browser, full TypeScript support |
| Node.js backend service | [WASM SDK](/docs/sdks/wasm-sdk) | Same WASM package works in Node.js |
| High-performance native app | [Rust Crates](/docs/sdks/rust-crates) | Direct access to all crates, zero overhead |
| Scripting and automation | [Python SDK](/docs/sdks/python-sdk) | Familiar syntax, fast prototyping |
| Analytics and data pipelines | [Python SDK](/docs/sdks/python-sdk) | Integrates with numpy, pandas, Jupyter |
| Go or C# application | [Community SDKs](/docs/sdks/community-sdks) | Community-maintained libraries |
| Custom protocol tooling | [Rust Crates](/docs/sdks/rust-crates) | Full control over consensus primitives |

## Common Capabilities

Regardless of which SDK you choose, the following operations are available across all official SDKs:

- **RPC communication** — Connect to a Kaspa node, query blockchain state (DAG info, block data, mempool), and submit transactions.
- **Wallet operations** — Generate mnemonics, derive HD keys (BIP-32 with Kaspa's `m/44'/111111'/` derivation path), and manage addresses.
- **Transaction construction** — Build transactions with automatic UTXO selection, fee calculation, and compound transaction chaining for large UTXO sets.
- **Address handling** — Create, parse, and validate Bech32-encoded Kaspa addresses across mainnet, testnet, and simnet.
- **Event subscriptions** — Subscribe to real-time notifications for UTXO changes, new blocks, DAA score updates, and virtual chain changes.
- **Signing** — Sign transactions using Schnorr signatures over secp256k1.

<Callout type="info">
All official SDKs derive from the same Rust codebase. The WASM SDK is compiled from Rust to WebAssembly, and the Python SDK uses PyO3 bindings to the Rust crates. This means consensus-critical logic is identical across SDKs.
</Callout>

## Transport Protocols

SDKs communicate with Kaspa nodes using one of two RPC protocols:

- **wRPC (WebSocket RPC)** — The primary protocol for application development. Supports both Borsh (binary) and JSON encodings. The WASM SDK's `Resolver` class can automatically discover public wRPC endpoints.
- **gRPC** — Used by infrastructure tools and some community SDKs. Requires direct node access and is not available through public endpoints by default.

<Callout type="warn">
Public wRPC nodes are provided for development convenience. Production applications that process real value should always connect to a node you operate. Public nodes may impose rate limits, go offline without notice, or be operated by untrusted parties.
</Callout>

## Network Identifiers

When connecting to a node, you must specify the target network. All SDKs use the same network identifier strings:

| Network | Identifier | Address Prefix | Use |
|---|---|---|---|
| Mainnet | `mainnet` | `kaspa:` | Production |
| Testnet 10 | `testnet-10` | `kaspatest:` | Testing (10 BPS) |
| Testnet 11 | `testnet-11` | `kaspatest:` | Testing (higher BPS) |
| Simnet | `simnet` | `kaspasim:` | Local development |

## Getting Started

Pick the SDK that matches your use case and follow the corresponding guide:

- **[WASM SDK](/docs/sdks/wasm-sdk)** — Installation, connecting to a node, wallet setup, and sending transactions from JavaScript or TypeScript.
- **[Rust Crates](/docs/sdks/rust-crates)** — Adding crates to your `Cargo.toml`, RPC connections, and transaction construction in Rust.
- **[Python SDK](/docs/sdks/python-sdk)** — Installing via pip, scripting wallet operations, and querying the network.
- **[Community SDKs](/docs/sdks/community-sdks)** — Go, C#, and other language bindings maintained by the community.

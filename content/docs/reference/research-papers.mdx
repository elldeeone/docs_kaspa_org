## Overview

Kaspa's protocol is built on peer-reviewed academic research. The core consensus algorithms have formal security proofs and are published in leading cryptography and distributed systems venues. This page provides summaries and links to the key papers.

## PHANTOM and GHOSTDAG

### PHANTOM: A Scalable BlockDAG Protocol

**Authors:** Yonatan Sompolinsky, Aviv Zohar

**Published:** 2018 (ePrint), updated through 2020

**Link:** [eprint.iacr.org/2018/104](https://eprint.iacr.org/2018/104)

**Summary:** PHANTOM introduces a protocol for ordering blocks in a BlockDAG (Directed Acyclic Graph) while distinguishing between honest and adversarial blocks. The key insight is the **k-cluster** property: under reasonable network delay assumptions, honest blocks form a well-connected cluster in the DAG, while adversarial blocks that withhold or delay publication create recognizable patterns.

PHANTOM defines a coloring rule that classifies blocks as **blue** (likely honest) or **red** (potentially adversarial), then constructs a total ordering of all blocks. The protocol generalizes Nakamoto's longest-chain rule to a DAG setting, proving that safety and liveness are preserved under a proof-of-work honest majority assumption.

**Key contributions:**
- Formal model for BlockDAG consensus
- k-cluster coloring algorithm for blue/red block classification
- Security proofs under bounded network delay
- Foundation for high-throughput PoW without orphan blocks

### GHOSTDAG: A Greedy Approach

**GHOSTDAG** is the practical implementation of PHANTOM's ideas, optimized for efficiency. While PHANTOM's optimal coloring is NP-hard to compute, GHOSTDAG uses a greedy algorithm that achieves equivalent security guarantees in polynomial time.

GHOSTDAG is the consensus protocol currently running on the Kaspa mainnet.

**Key properties:**
- Greedy selection of the heaviest blue sub-DAG
- O(k) per-block computation
- Deterministic ordering from any DAG state
- Backward-compatible with Nakamoto consensus (a blockchain is a DAG with k=0)

## DAGKnight

### DAGKnight: A Parameterless Generalization of Nakamoto Consensus

**Authors:** Yonatan Sompolinsky, Aviv Zohar

**Published:** 2022 (ePrint)

**Link:** [eprint.iacr.org/2022/1494](https://eprint.iacr.org/2022/1494)

**Summary:** DAGKnight extends GHOSTDAG by removing the need for a fixed `k` parameter. In GHOSTDAG, the `k` value must be set based on assumptions about network delay and block rate. If the assumed delay is too low, security degrades. DAGKnight adapts dynamically to observed network conditions.

**Key contributions:**
- **Parameterless consensus**: No need to pre-configure `k` based on network delay assumptions.
- **Optimal confirmation times**: Achieves confirmation times that are a function of the actual (not assumed) network delay.
- **Adaptive security**: The protocol's security adapts to real network conditions rather than worst-case assumptions.
- **Generalization of Nakamoto**: Provably reduces to Nakamoto consensus in the chain case.

<Callout type="info">
DAGKnight is planned as a future upgrade to Kaspa's consensus. The current mainnet runs GHOSTDAG with a fixed k parameter. DAGKnight will allow the network to operate without pre-configured delay assumptions while achieving faster confirmation times.
</Callout>

## SPECTRE

### SPECTRE: Serialization of Proof-of-work Events

**Authors:** Yonatan Sompolinsky, Yoad Lewenberg, Aviv Zohar

**Published:** 2016

**Summary:** SPECTRE is an earlier BlockDAG protocol by the same research group. It provides fast confirmation times by using a voting mechanism where blocks "vote" on the ordering of other blocks. However, SPECTRE only provides a **partial ordering** of transactions — it can determine which of two conflicting transactions came first, but does not provide a total ordering of all blocks.

**Relationship to Kaspa:** SPECTRE influenced the design of PHANTOM/GHOSTDAG. While SPECTRE excels at fast confirmations for individual transactions, PHANTOM/GHOSTDAG provides the total ordering needed for a general-purpose cryptocurrency (where applications may need to know the order of all transactions, not just conflicting pairs).

## Inclusive Blockchain Protocols

### Inclusive Block Chain Protocols

**Authors:** Yoad Lewenberg, Yonatan Sompolinsky, Aviv Zohar

**Published:** 2015 (FC 2015)

**Summary:** This paper introduces the concept of "inclusive" blockchain protocols that reward all miners for their blocks, even when multiple blocks are found at the same height. The paper proposes mechanisms where off-chain blocks (which would be orphans in Bitcoin) contribute to the ledger and their miners receive partial rewards.

**Relationship to Kaspa:** The inclusive approach is a philosophical ancestor of Kaspa's BlockDAG. By including all blocks in the DAG rather than discarding orphans, Kaspa achieves the fairness and efficiency goals proposed in this paper.

## Related Work

### On the Security and Performance of Proof of Work Blockchains

**Authors:** Arthur Gervais, Ghassan O. Karame, Karl Wüst, Vasileios Glykantzis, Hubert Ritzdorf, Srdjan Capkun

**Published:** 2016 (CCS 2016)

**Summary:** A comprehensive analysis of PoW blockchain security, including the impact of block size, block interval, and network propagation on security. This work provides the theoretical framework for understanding why increasing the block rate in a traditional blockchain degrades security — the exact problem that BlockDAG protocols solve.

### The Bitcoin Backbone Protocol

**Authors:** Juan Garay, Aggelos Kiayias, Nikos Leonardos

**Published:** 2015

**Summary:** Formal security analysis of Bitcoin's consensus protocol, establishing the properties of **common prefix**, **chain quality**, and **chain growth**. These properties serve as the baseline that GHOSTDAG and DAGKnight extend to the DAG setting.

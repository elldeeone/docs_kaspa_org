## Overview

Kaspa uses a **chromatic emission schedule** — named after the 12 semitones in a musical chromatic scale. Instead of Bitcoin's abrupt 50% halving every ~4 years, Kaspa reduces the block reward by a factor of `(1/2)^(1/12)` each month, producing a smooth exponential decay.

Over the course of 12 months, the cumulative reduction equals exactly 50%, achieving the same long-term supply curve as Bitcoin but without the sharp halving events.

## Monthly Reduction Factor

The per-month reduction factor is:

```
factor = (1/2)^(1/12) ≈ 0.94387431268
```

Each month, the block reward is multiplied by this factor. After 12 months, the reward is exactly half of its starting value:

```
0.94387431268^12 = 0.5
```

## Block Reward Calculation

The block reward at any point is determined by the DAA score. The emission schedule divides time into monthly phases, with the reward decreasing by the chromatic factor at each phase boundary.

In consensus, a "month" for subsidy purposes is defined as `2,629,800` seconds (30.4375 days), not a fixed 30-day bucket:

```
SECONDS_PER_MONTH = 2,629,800
subsidy_month = floor(seconds_since_deflationary_phase_started / SECONDS_PER_MONTH)
```

At 10 BPS, that corresponds to `26,298,000` DAA-score units per subsidy month-equivalent period.
Across the Crescendo boundary, subsidy-month calculation first converts DAA-score distance to seconds using the pre/post-fork BPS and only then divides by `SECONDS_PER_MONTH`.
([source](https://github.com/kaspanet/rusty-kaspa/blob/master/consensus/src/processes/coinbase.rs#L21-L24), [source](https://github.com/kaspanet/rusty-kaspa/blob/master/consensus/src/processes/coinbase.rs#L239-L254))

## Supply Progression

Supply percentages over specific calendar years depend on the exact genesis start point and phase boundaries used in the calculation. For canonical totals, prefer consensus-derived values from the `rusty-kaspa` subsidy table and coinbase logic rather than simplified year buckets.

<Callout type="info">
Under current consensus rules, total emitted supply is approximately **28.38 billion KAS**. Changing emission behavior requires a consensus upgrade (hardfork).
</Callout>

## Reward Distribution in a DAG

In Kaspa's BlockDAG, block rewards follow special rules:

- **Blue blocks**: The miner of a blue block receives the full block subsidy plus all transaction fees from that block.
- **Red blocks**: The subsidy and fees from red blocks are **not** paid to the red block's miner. Instead, they are collected by the miner of the block that merges the red block into the DAG.
- **Coinbase maturity**: Coinbase outputs cannot be spent until they reach a maturity depth of **1,000 DAA score** (at 10 BPS), corresponding to approximately 100 seconds.

This incentive structure encourages miners to follow the GHOSTDAG protocol honestly, as blocks that deviate from the protocol are more likely to be classified as red and lose their rewards.

## Comparison with Bitcoin

| Property | Bitcoin | Kaspa |
|----------|---------|-------|
| Halving style | Abrupt 50% every ~4 years | Smooth ~5.6% monthly reduction |
| Halving period | ~210,000 blocks | 12 chromatic phases (~1 year) |
| Max supply | 21 million BTC | ~28.38 billion KAS (current consensus schedule) |
| Smallest unit | 1 satoshi (10^-8 BTC) | 1 sompi (10^-8 KAS) |

## Implementation

The emission schedule is implemented in the coinbase subsidy calculation within the consensus engine. The reward for any given DAA score is deterministically computed from the emission table, ensuring all nodes agree on the correct block reward.

The subsidy table is precomputed as an array of reward values indexed by the emission phase. The phase is derived from the block's DAA score using integer division by the phase length (in blocks).

## Overview

Solo mining means you run your own Kaspa full node and mine directly against the network without sharing rewards with a pool. When you find a block, you receive the entire block reward. However, because you are competing against the total network hashrate, solo mining is only practical if you have sufficient hashing power to find blocks at a reasonable frequency.

With Kaspa producing 10 blocks per second, solo miners with moderate hashrate can find blocks more frequently than on slower blockchains, making solo mining more viable than it is on networks like Bitcoin.

<Callout type="warn">
Solo mining requires running a full Kaspa node and keeping it synced at all times. If your node falls behind the DAG tip, your mined blocks will be rejected by the network.
</Callout>

## Requirements

Before you begin, ensure you have the following:

- **Hardware**: A GPU with sufficient hashrate (see the [Hardware](/docs/mining/hardware) page for recommendations) or an ASIC miner.
- **Full node**: A running and fully synced instance of `kaspad` (the Kaspa full node daemon).
- **Mining software**: A compatible miner such as `kaspa-miner`, BzMiner, lolMiner, or another kHeavyHash-compatible GPU/ASIC miner.
- **Kaspa wallet address**: A Kaspa address to receive block rewards. You can generate one using the Kaspa CLI wallet (`kaspa-cli`), the Kaspa desktop wallet, or the KDX application.
- **Stable internet connection**: Low latency is important at 10 BPS to ensure your blocks propagate quickly.
- **Sufficient disk space**: The Kaspa UTXO set and DAG headers require storage. Plan for at least 50 GB of free disk space, with room to grow.

## Step 1: Set Up kaspad

Download and build or install `kaspad` from the official Kaspa repository. Then start the node with the required flags for mining.

### Running kaspad with Mining Enabled

```bash
kaspad --utxoindex --mining-address=kaspa:qr...your_address_here
```

**Key flags:**

| Flag | Purpose |
|---|---|
| `--utxoindex` | Enables the UTXO index, which is required for mining and wallet operations. Without this flag, the node cannot construct block templates. |
| `--mining-address` | Specifies the Kaspa address that will receive block rewards. |

<Callout type="info">
The `--utxoindex` flag causes `kaspad` to maintain an additional index over the UTXO set. This increases disk usage and initial sync time but is mandatory for mining. If you previously ran `kaspad` without this flag, you may need to re-sync from scratch or use `--reset-db` to rebuild the database with the index.
</Callout>

### Optional Flags

```bash
kaspad --utxoindex \
  --mining-address=kaspa:qr...your_address_here \
  --rpclisten=0.0.0.0:16110 \
  --listen=0.0.0.0:16111
```

| Flag | Purpose |
|---|---|
| `--rpclisten` | Sets the gRPC listen address. Default is `localhost:16110`. Set to `0.0.0.0:16110` if your miner runs on a different machine. |
| `--listen` | Sets the P2P listen address. Default is `0.0.0.0:16111`. |

### Wait for Sync

After starting `kaspad`, wait for it to fully sync with the network. You can monitor sync progress in the log output. The node will display messages indicating the current blue score and DAG tip as it catches up.

```
[INF] Blue score: 58234012, DAG tip timestamp: 2025-12-01 14:22:33
```

Mining before the node is fully synced will result in rejected blocks.

## Step 2: Connect Your Miner

Once `kaspad` is running and synced, connect your mining software to the node's gRPC endpoint.

### Using kaspa-miner (Rust GPU Miner)

`kaspa-miner` is the reference GPU miner for Kaspa, written in Rust.

```bash
kaspa-miner --mining-address kaspa:qr...your_address_here \
  --kaspad-address 127.0.0.1:16110 \
  --num-gpu-threads 1 \
  --gpu-threads-per-device 2
```

| Flag | Purpose |
|---|---|
| `--mining-address` | Your Kaspa wallet address. |
| `--kaspad-address` | The gRPC address of your running `kaspad` instance. |
| `--num-gpu-threads` | Number of GPUs to use. |
| `--gpu-threads-per-device` | Threads per GPU (tuning depends on your GPU model). |

### Using BzMiner

BzMiner supports kHeavyHash natively. For solo mining, point it at your local `kaspad` gRPC endpoint:

```bash
bzminer -a kaspa -w kaspa:qr...your_address_here \
  -p 127.0.0.1:16110 --no_stratum
```

<Callout type="info">
When solo mining with BzMiner or similar multi-algorithm miners, ensure you specify `kaspa` (or `kheavyhash`) as the algorithm. The `--no_stratum` or equivalent flag tells the miner to use gRPC directly rather than the stratum pool protocol.
</Callout>

### Using lolMiner

```bash
lolMiner --algo KASPA --pool 127.0.0.1:16110 \
  --user kaspa:qr...your_address_here --solo
```

## Step 3: Monitor Your Mining

### Hashrate Monitoring

Your mining software will report the current hashrate in its console output. Typical output looks like:

```
[INFO] GPU #0: 580 MH/s | GPU #1: 575 MH/s | Total: 1.155 GH/s
[INFO] Shares: 42 accepted, 0 rejected
```

For solo mining, "shares" or "blocks" found represents actual blocks submitted to the network.

### Checking Block Rewards

You can verify that blocks you mined are being accepted by querying your node or checking your wallet balance:

```bash
kaspa-cli --rpcserver=127.0.0.1:16110 getbalancebyaddress kaspa:qr...your_address_here
```

You can also use a Kaspa block explorer to search your mining address and confirm that mined blocks appear with your address as the coinbase recipient.

### Expected Block Frequency

Your expected time between blocks depends on your share of the total network hashrate:

```
Expected blocks per day = (your_hashrate / network_hashrate) * 10 BPS * 86400 seconds
```

For example, if the network hashrate is 50 TH/s and you have 5 GH/s:

```
(5 / 50,000,000) * 10 * 86400 = 0.0864 blocks/day ~ 1 block every ~11.5 days
```

<Callout type="warn">
Solo mining income is highly variable. You may go long periods without finding a block, then find several in quick succession. Pool mining provides more consistent payouts if income stability is important to you. See the [Pool Mining](/docs/mining/pool-mining) guide for details.
</Callout>

## Troubleshooting

### Common Issues

| Problem | Likely Cause | Solution |
|---|---|---|
| Miner cannot connect to kaspad | gRPC port not accessible | Check `--rpclisten` flag and firewall rules. |
| Blocks found but not accepted | Node not fully synced | Wait for full sync before mining. |
| Low hashrate | Incorrect GPU thread configuration | Experiment with `--gpu-threads-per-device` values. |
| "UTXO index not available" error | Missing `--utxoindex` flag | Restart `kaspad` with `--utxoindex`. May require `--reset-db`. |

### Performance Tips

- **Dedicated machine**: Run `kaspad` on a machine with low-latency internet and an SSD for best DAG sync performance.
- **Separate miner and node**: If running on separate machines, ensure the network link between them has minimal latency (ideally same LAN).
- **Keep software updated**: Kaspa node software and miners are actively developed. New releases often include performance improvements and bug fixes.
- **Monitor DAG sync**: If your node falls behind the DAG tip, blocks you mine will be stale. Set up monitoring to alert you if the node stops syncing.

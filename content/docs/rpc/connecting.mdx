## Port Reference

Each Kaspa network uses a distinct set of ports for its various interfaces. The port scheme follows a consistent pattern based on a network suffix.

### Mainnet and Testnet Ports

| Network | P2P | gRPC | wRPC Borsh | wRPC JSON |
|---------|-----|------|------------|-----------|
| **Mainnet** | 16111 | 16110 | 17110 | 18110 |
| **Testnet-10** | 16211 | 16210 | 17210 | 18210 |
| **Testnet-11** | 16311 | 16210 | 17210 | 18210 |

### Development Network Ports

| Network | P2P | gRPC | wRPC Borsh | wRPC JSON |
|---------|-----|------|------------|-----------|
| **Simnet** | 16511 | 16510 | 17510 | 18510 |
| **Devnet** | 16611 | 16610 | 17610 | 18610 |

<Callout type="info">
The P2P port is for node-to-node communication and is not used by RPC clients. Your application connects to the gRPC or wRPC ports.
</Callout>

### Customizing Ports

RPC interface ports can be changed when running `kaspad` using the following arguments:

| Argument | Interface |
|----------|-----------|
| `--rpclisten` | gRPC listen address and port |
| `--rpclisten-borsh` | wRPC Borsh listen address and port |
| `--rpclisten-json` | wRPC JSON listen address and port |

For local-only access, bind to `127.0.0.1` or `localhost`. For public access, bind to `0.0.0.0` or a specific IP address:

```bash
# Local-only gRPC access
kaspad --rpclisten=127.0.0.1:16110

# Public wRPC Borsh access on all interfaces
kaspad --rpclisten-borsh=0.0.0.0:17110

# Custom port for wRPC JSON
kaspad --rpclisten-json=0.0.0.0:19000
```

## Connection URLs

### wRPC (WebSocket)

```
ws://<host>:<port>
```

For mainnet with Borsh encoding:
```
ws://127.0.0.1:17110
```

For mainnet with JSON encoding:
```
ws://127.0.0.1:18110
```

For TLS-secured connections (requires a reverse proxy):
```
wss://<host>:<port>
```

### gRPC

```
grpc://<host>:<port>
```

For mainnet:
```
grpc://127.0.0.1:16110
```

### REST

```
https://api.kaspa.org
```

The REST API is a public service and does not require running your own node.

## Connection Methods

There are three ways to define which node to connect to, listed by priority:

1. **Programmatic URL at connect time** (highest priority) -- Pass the URL directly when calling `connect()`
2. **Constructor-level URL** -- Specify the URL when creating the RPC client
3. **Resolver-based discovery** (lowest priority) -- Let the Resolver return a public endpoint when no URL is provided

## Using the Resolver for Automatic Node Discovery

The Resolver asks resolver infrastructure for a connectable endpoint. Resolver-side routing policy is operational behavior (not part of the node RPC protocol), so exact selection criteria can change over time.

### JavaScript / TypeScript (Browser and Node.js)

```typescript
import { RpcClient, Resolver, Encoding } from "kaspa-wasm";

// Create client with Resolver -- no URL needed
const rpc = new RpcClient({
  resolver: new Resolver(),
  encoding: Encoding.Borsh,
  networkId: "mainnet",
});

await rpc.connect();
const info = await rpc.getBlockDagInfo();
console.log("Network:", info.network);
console.log("DAA score:", info.virtualDaaScore);
```

For testnet, change the `networkId`:

```typescript
const rpc = new RpcClient({
  resolver: new Resolver(),
  encoding: Encoding.Borsh,
  networkId: "testnet-10",
});
await rpc.connect();
```

### Rust

```rust
use kaspa_wrpc_client::prelude::*;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let resolver = Resolver::default();

    let client = KaspaRpcClient::new(
        WrpcEncoding::Borsh,
        None,
        Some(resolver),
        Some(NetworkId::new(NetworkType::Mainnet)),
        None,
    )?;

    client.connect(None).await?;

    let info = client.get_block_dag_info().await?;
    println!("Network: {}", info.network);
    println!("DAA score: {}", info.virtual_daa_score);

    client.disconnect().await?;
    Ok(())
}
```

<Callout type="info">
Operational note (non-normative): resolver-based clients typically reconnect by requesting a fresh endpoint after disconnects. Exact retry/backoff and endpoint-selection behavior depends on SDK and resolver versions.
</Callout>

## Direct Connection to Your Own Node

If you run your own node, connect directly by specifying the URL. This is the recommended approach for production applications.

### JavaScript / TypeScript -- URL at Constructor

```typescript
import { RpcClient, Encoding } from "kaspa-wasm";

const rpc = new RpcClient({
  url: "ws://127.0.0.1:17110",
  encoding: Encoding.Borsh,
  networkId: "mainnet",
});

await rpc.connect();
const info = await rpc.getInfo();
console.log("Connected to node:", info.serverVersion);
```

### JavaScript / TypeScript -- URL at Connect Time

You can also pass the URL when calling `connect()`, which overrides any URL set in the constructor:

```typescript
import { RpcClient, Encoding } from "kaspa-wasm";

const rpc = new RpcClient({
  encoding: Encoding.Borsh,
  networkId: "mainnet",
});

// URL passed at connect time takes highest priority
await rpc.connect({ url: "ws://192.168.1.100:17110" });
```

### Rust -- URL at Constructor

```rust
use kaspa_wrpc_client::prelude::*;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = KaspaRpcClient::new(
        WrpcEncoding::Borsh,
        Some("ws://127.0.0.1:17110"),
        None,
        Some(NetworkId::new(NetworkType::Mainnet)),
        None,
    )?;

    client.connect(None).await?;

    let info = client.get_info().await?;
    println!("Connected: {}", info.server_version);

    client.disconnect().await?;
    Ok(())
}
```

### Rust -- URL at Connect Time

```rust
use kaspa_wrpc_client::prelude::*;

let client = KaspaRpcClient::new(
    WrpcEncoding::Borsh,
    None,
    None,
    Some(NetworkId::new(NetworkType::Mainnet)),
    None,
)?;

client
    .connect(Some(ConnectOptions {
        url: Some("ws://127.0.0.1:17110".to_string()),
        ..Default::default()
    }))
    .await?;
```

## Connecting via gRPC

gRPC connections require direct access to a Kaspa node. Public gRPC endpoints are generally not available through the PNN.

### Rust

```rust
use kaspa_grpc_client::GrpcClient;
use kaspa_rpc_core::api::rpc::RpcApi;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = GrpcClient::connect("grpc://127.0.0.1:16110".to_string()).await?;

    let dag_info = client.get_block_dag_info().await?;
    println!("Network: {}", dag_info.network);
    println!("Block count: {}", dag_info.block_count);

    client.disconnect().await?;
    Ok(())
}
```

### Python

```python
import grpc
from generated import messages_pb2, messages_pb2_grpc

def requests():
    yield messages_pb2.KaspadRequest(
        id=1,
        getBlockDagInfoRequest=messages_pb2.GetBlockDagInfoRequestMessage(),
    )

channel = grpc.insecure_channel("127.0.0.1:16110")
stub = messages_pb2_grpc.RPCStub(channel)
stream = stub.MessageStream(requests())

for response in stream:
    if response.HasField("getBlockDagInfoResponse"):
        info = response.getBlockDagInfoResponse
        if info.error and info.error.message:
            raise RuntimeError(info.error.message)
        print(f"Network: {info.networkName}")
        print(f"Block count: {info.blockCount}")
        break
```

The `.proto` files for generating client code are available at [github.com/kaspanet/rusty-kaspa/tree/master/rpc/grpc/core/proto](https://github.com/kaspanet/rusty-kaspa/tree/master/rpc/grpc/core/proto).

### Go

```go
package main

import (
    "context"
    "fmt"
    "log"

    pb "your-module/generated/proto"
    "google.golang.org/grpc"
    "google.golang.org/grpc/credentials/insecure"
)

func main() {
    conn, err := grpc.Dial(
        "127.0.0.1:16110",
        grpc.WithTransportCredentials(insecure.NewCredentials()),
    )
    if err != nil {
        log.Fatalf("Failed to connect: %v", err)
    }
    defer conn.Close()

    client := pb.NewRPCClient(conn)
    stream, err := client.MessageStream(context.Background())
    if err != nil {
        log.Fatalf("MessageStream failed: %v", err)
    }

    err = stream.Send(&pb.KaspadRequest{
        Id: 1,
        Payload: &pb.KaspadRequest_GetBlockDagInfoRequest{
            GetBlockDagInfoRequest: &pb.GetBlockDagInfoRequestMessage{},
        },
    })
    if err != nil {
        log.Fatalf("Send failed: %v", err)
    }

    resp, err := stream.Recv()
    if err != nil {
        log.Fatalf("Recv failed: %v", err)
    }
    msg, ok := resp.Payload.(*pb.KaspadResponse_GetBlockDagInfoResponse)
    if !ok {
        log.Fatalf("Unexpected payload type: %T", resp.Payload)
    }
    if msg.GetBlockDagInfoResponse().GetError() != nil &&
        msg.GetBlockDagInfoResponse().GetError().GetMessage() != "" {
        log.Fatalf("RPC error: %s", msg.GetBlockDagInfoResponse().GetError().GetMessage())
    }

    info := msg.GetBlockDagInfoResponse()

    fmt.Printf("Network: %s\n", info.GetNetworkName())
    fmt.Printf("Block count: %d\n", info.GetBlockCount())
}
```

## REST API

The public REST API at `api.kaspa.org` requires no SDK or node setup:

```bash
# Get current coin supply
curl https://api.kaspa.org/info/coinsupply

# Get balance for an address
curl https://api.kaspa.org/addresses/<address>/balance

curl https://api.kaspa.org/blocks/<block-hash>
```

See the [REST API reference](/docs/rpc/rest/network-info) for the full list of available endpoints.

## Connecting to a Local Node

If you run your own `kaspad` or `rusty-kaspa` node, gRPC is enabled on localhost by default. wRPC listeners are enabled when you pass `--rpclisten-borsh` and/or `--rpclisten-json`. Ensure the node is synced before relying on RPC responses -- use `GetSyncStatus` or `GetInfo` to verify.

Start a node with custom listen addresses:

```bash
# Listen for gRPC on all interfaces
kaspad --rpclisten=0.0.0.0:16110

# Listen for wRPC Borsh on all interfaces
kaspad --rpclisten-borsh=0.0.0.0:17110

# Listen for wRPC JSON on all interfaces
kaspad --rpclisten-json=0.0.0.0:18110
```

<Callout type="warn">
Binding RPC to `0.0.0.0` exposes the interface to all network traffic. Kaspa's RPC has no built-in authentication. Use firewall rules, a VPN, or a reverse proxy to control access when binding to public addresses.
</Callout>

## TLS and Reverse Proxy Setup

Kaspa's RPC does not natively support TLS. For encrypted connections:

1. Use a reverse proxy (NGINX, Caddy, HAProxy) that terminates TLS and forwards to the local RPC port
2. Use an SSH tunnel for remote development
3. Use a VPN between your application and the node

### NGINX Proxy Example

The following NGINX configuration routes WebSocket traffic to Kaspa nodes based on URL path, supporting multiple networks and encodings through a single proxy:

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name *.example.com;
    client_max_body_size 1m;

    # Mainnet wRPC Borsh
    location /mainnet/wrpc/borsh {
        proxy_pass http://127.0.0.1:17110;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # Mainnet wRPC JSON
    location /mainnet/wrpc/json {
        proxy_pass http://127.0.0.1:18110;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # Testnet-10 wRPC Borsh
    location /testnet-10/wrpc/borsh {
        proxy_pass http://127.0.0.1:17210;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # Testnet-10 wRPC JSON
    location /testnet-10/wrpc/json {
        proxy_pass http://127.0.0.1:18210;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # Testnet-11 wRPC Borsh (same RPC ports as testnet-10; only P2P port differs)
    location /testnet-11/wrpc/borsh {
        proxy_pass http://127.0.0.1:17210;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # Testnet-11 wRPC JSON
    location /testnet-11/wrpc/json {
        proxy_pass http://127.0.0.1:18210;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

<Callout type="info">
NGINX connection capacity depends on your `worker_connections` and worker process settings. For high-traffic deployments, tune `worker_connections` in `nginx.conf` and validate limits under load. When using `wss://` through a reverse proxy, ensure the proxy supports WebSocket upgrade headers.
</Callout>

## Connection Options and Configuration

### Encoding Selection

Choose between Borsh and JSON encoding based on your use case:

| Encoding | Port (Mainnet) | Best For |
|----------|----------------|----------|
| **Borsh** | 17110 | Performance-sensitive apps, Rust/WASM clients |
| **JSON** | 18110 | Debugging, third-party integrations, browser dev tools |

Both encodings expose identical methods and return identical logical data.

### Network Selection

When connecting, you must specify the target network:

| Network | Identifier | Address Prefix |
|---------|------------|----------------|
| Mainnet | `mainnet` | `kaspa:` |
| Testnet-10 | `testnet-10` | `kaspatest:` |
| Testnet-11 | `testnet-11` | `kaspatest:` |
| Simnet | `simnet` | `kaspasim:` |

## Error Handling and Reconnection

### JavaScript / TypeScript

```typescript
import { RpcClient, Resolver, Encoding } from "kaspa-wasm";

const rpc = new RpcClient({
  resolver: new Resolver(),
  encoding: Encoding.Borsh,
  networkId: "mainnet",
});

try {
  await rpc.connect();
  const info = await rpc.getBlockDagInfo();
  console.log("Connected:", info.network);
} catch (error) {
  console.error("Connection failed:", error.message);
}

// Listen for disconnect events
rpc.addEventListener("disconnect", (event) => {
  console.log("Disconnected from node");
  // Resolver-based clients can reconnect by resolving a fresh endpoint.
  // For direct connections, implement reconnection logic:
  // setTimeout(() => rpc.connect(), 5000);
});
```

<Callout type="info">
Operational note (non-normative): many resolver-based deployments rely on automatic endpoint re-resolution during reconnects. For direct URL connections, implement your own reconnect and resubscribe logic.
</Callout>

### Common Errors

| Typical Error | Likely Cause | Typical Resolution |
|-------|-------|------------|
| Connection refused | Node is not running or port is wrong | Verify node is running and port matches the encoding |
| Connection timeout | Node is unreachable or firewall blocking | Check network connectivity and firewall rules |
| WebSocket upgrade failed | Proxy not configured for WebSocket | Ensure proxy passes `Upgrade` and `Connection` headers |
| SSL required | Browser blocking non-TLS connection | Use `wss://` with a TLS-terminating proxy, or use desktop app |

## Connection Lifecycle

1. **Connect**: Establish a WebSocket or gRPC connection to the node.
2. **Verify state**: Optionally call `GetInfo`/`GetSyncStatus` before serving user traffic.
3. **Request/Response**: Send RPC method calls and receive responses.
4. **Subscribe**: Optionally subscribe to notifications for real-time updates.
5. **Reconnect handling**: On disconnect, reconnect and resubscribe as needed.
6. **Disconnect**: Close the connection gracefully when done.

## Verifying a Connection

After connecting, verify the node is synced and operational:

```typescript
const info = await rpc.getInfo();
console.log("Server version:", info.serverVersion);
console.log("Is synced:", info.isSynced);
console.log("UTXO indexed:", info.isUtxoIndexed);

if (!info.isSynced) {
  console.warn("Node is still syncing -- RPC responses may be incomplete");
}
```

<Callout type="warn">
Always check `isSynced` before relying on RPC responses for transactions or balance queries.
</Callout>

## Base URL

All REST API endpoints are served from the public Kaspa API:

```
https://api.kaspa.org
```

<Callout type="info">
The public REST API at `api.kaspa.org` is provided for development and light usage. For production applications that process real value or require high availability, run your own instance of the [kaspa-rest-server](https://github.com/kaspa-ng/kaspa-rest-server) connected to your own node.
</Callout>

## GET /addresses/\{address\}/balance

Returns the total balance for a single address, calculated by summing all of its unspent transaction outputs.

**Request:**

```
GET https://api.kaspa.org/addresses/kaspa:qqkqkzjvr7zwxxmjxjkmxxdwju9kjs6e9u82uh59z07vgaks6gg62v8707g73/balance
```

**Response:**

```json
{
  "address": "kaspa:qqkqkzjvr7zwxxmjxjkmxxdwju9kjs6e9u82uh59z07vgaks6gg62v8707g73",
  "balance": 500000000000
}
```

<Callout>
Balances are returned in **sompi** (the smallest unit of KAS). 1 KAS = 100,000,000 sompi. Divide by 10^8 to convert to KAS.
</Callout>

## GET /addresses/\{address\}/full-transactions

Returns the full transaction history for an address, including both inputs and outputs with complete transaction details.

**Request:**

```
GET https://api.kaspa.org/addresses/kaspa:qqkqkzjvr7zwxxmjxjkmxxdwju9kjs6e9u82uh59z07vgaks6gg62v8707g73/full-transactions
```

**Query Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `limit` | integer | Maximum number of transactions to return (default: 50) |
| `offset` | integer | Number of transactions to skip for pagination |
| `resolve_previous_outpoints` | string | Previous outpoint lookup mode: `no` (default), `light`, or `full` |

**Response:**

## GET /addresses/\{address\}/full-transactions-page

Returns a cursor-style paginated view of full transactions for an address.

**Request:**

```
GET https://api.kaspa.org/addresses/kaspa:qr35enn.../full-transactions-page?limit=50&before=1772184825747&resolve_previous_outpoints=light
```

**Query Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `limit` | integer | Maximum number of records to return (default: `50`, max: `500`) |
| `before` | integer | Include only transactions with `block_time` before this epoch-millis value |
| `after` | integer | Include only transactions with `block_time` after this epoch-millis value |
| `resolve_previous_outpoints` | string | Previous outpoint lookup mode: `no`, `light`, or `full` |
| `acceptance` | string | Optional acceptance filter |

**Response:**

The response is a JSON array of transactions (same shape as `/full-transactions`), and pagination cursors are returned via HTTP headers such as `x-next-page-before`.

## GET /addresses/\{address\}/transactions-count

Returns the total number of transactions associated with an address.

**Request:**

```
GET https://api.kaspa.org/addresses/kaspa:qqkqkzjvr7zwxxmjxjkmxxdwju9kjs6e9u82uh59z07vgaks6gg62v8707g73/transactions-count
```

**Response:**

```json
{
  "total": 1523
}
```

## Querying Multiple Addresses

For multiple addresses, use the dedicated POST endpoints:

```
POST https://api.kaspa.org/addresses/balances
Content-Type: application/json
```

```json
{
  "addresses": [
    "kaspa:addr1",
    "kaspa:addr2",
    "kaspa:addr3"
  ]
}
```

For UTXOs:

```
POST https://api.kaspa.org/addresses/utxos
Content-Type: application/json
```

```json
{
  "addresses": [
    "kaspa:addr1",
    "kaspa:addr2"
  ]
}
```

`/addresses/balances` returns an array of `{ address, balance }` entries, and `/addresses/utxos` returns an array of UTXO entries for the requested addresses.

## Service Limits

Public `api.kaspa.org` usage policies can change over time and may vary by endpoint or infrastructure conditions. For sustained high-volume traffic, run your own REST server instance.

<Callout type="info">
For high-volume use cases such as exchange integrations, wallet backends, or analytics platforms, deploy your own REST API server. This gives you full control over availability and performance.
</Callout>

## Error Responses

Errors are returned with endpoint-specific HTTP status codes:

| Status Code | Meaning |
|---|---|
| `200` | Success |
| `404` | Resource not found (endpoint dependent) |
| `422` | Validation error (invalid address format, unknown query parameter, etc.) |

Validation errors follow a `detail` schema:

```json
{
  "detail": [
    {
      "loc": ["path", "kaspaAddress"],
      "msg": "string does not match regex \"^kaspa:[a-z0-9]{61,63}$\"",
      "type": "value_error.str.regex"
    }
  ]
}
```

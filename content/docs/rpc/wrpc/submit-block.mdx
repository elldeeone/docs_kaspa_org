---
title: "SubmitBlock"
description: "Submit a solved block to the network for validation and inclusion in the DAG."
---

## Request

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `block` | object | Yes | The complete block with a solved header (valid nonce). |
| `allowNonDAABlocks` | boolean | No | Whether to allow blocks that do not comply with DAA rules. Defaults to `false`. Only used in testing. |

## Response

| Field | Type | Description |
|-------|------|-------------|
| `report` | object | The result of block submission as a tagged object. |
| `report.type` | string | Either `"success"` or `"reject"`. |
| `report.reason` | string | Only present when `type` is `"reject"`. The rejection reason (e.g., `"blockInvalid"`). |

## Example

```json
// Request
{
  "method": "submitBlock",
  "params": {
    "block": {
      "header": {
        "version": 1,
        "parentsByLevel": [["aabb1122..."]],
        "hashMerkleRoot": "ccdd3344...",
        "timestamp": 1700000000000,
        "bits": 1234567890,
        "nonce": 42,
        "daaScore": 50000000,
        "blueScore": 48000000
      },
      "transactions": []
    },
    "allowNonDAABlocks": false
  }
}

// Response (success)
{
  "report": {
    "type": "success"
  }
}

// Response (rejected)
{
  "report": {
    "type": "reject",
    "reason": "blockInvalid"
  }
}
```

## Notes

- A `"success"` report type means the block was accepted and will be propagated to peers.
- A `"reject"` report type means the block failed validation (invalid PoW, bad timestamps, etc.) and includes a `reason` field.
- The block object should be the template from `GetBlockTemplate` with the nonce field updated to the solved value.
- Mining software typically calls `GetBlockTemplate`, solves the nonce, and calls `SubmitBlock` in a tight loop.

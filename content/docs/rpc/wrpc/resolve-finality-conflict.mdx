---
title: "ResolveFinalityConflict"
description: "Resolve a finality conflict by specifying a finality block hash (currently unimplemented)."
---

## Request

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `finalityBlockHash` | string | Yes | The hash of the block to set as the finality point. |

## Response

Current node behavior: this method returns a `NotImplemented` error.

## Example

```json
// Request
{
  "method": "resolveFinalityConflict",
  "params": {
    "finalityBlockHash": "6ef1913d30d5063e040839fcc67cbf02e8e0ae6e4a3cb774c7777043399697f5"
  }
}

// Response
{
  "error": {
    "message": "Not implemented"
  }
}
```

## Notes

<Callout>
This is an administrative method and is unavailable in safe RPC mode. Run the node with `--unsaferpc` to call it.
</Callout>

- A finality conflict occurs when the node detects two competing chains that both have sufficient depth to be considered final.
- Under normal network conditions, finality conflicts do not occur. This method exists as a safety mechanism for extraordinary situations.
- Current implementations return `NotImplemented`, so do not rely on this method for automated recovery flows.

---
title: "GetMetrics"
description: "Get comprehensive performance and resource metrics from the node."
---

## Request

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `processMetrics` | boolean | No | Whether to include process metrics (CPU, memory, etc.). |
| `connectionMetrics` | boolean | No | Whether to include connection metrics. |
| `bandwidthMetrics` | boolean | No | Whether to include bandwidth metrics. |
| `consensusMetrics` | boolean | No | Whether to include consensus metrics. |
| `storageMetrics` | boolean | No | Whether to include storage metrics. |
| `customMetrics` | boolean | No | Whether to include custom metrics. |

## Response

| Field | Type | Description |
|-------|------|-------------|
| `processMetrics` | object | CPU usage, resident memory, virtual memory, file descriptors used. |
| `connectionMetrics` | object | Active P2P and RPC connections, inbound/outbound counts. |
| `bandwidthMetrics` | object | Network bandwidth usage (bytes sent/received). |
| `consensusMetrics` | object | Consensus-related metrics: blocks processed, headers processed, DAG stats. |
| `storageMetrics` | object | Database size and storage usage statistics. |
| `serverTime` | u64 | The current server time in milliseconds since epoch. |

## Example

```json
// Request
{
  "method": "getMetrics",
  "params": {
    "processMetrics": true,
    "connectionMetrics": true,
    "bandwidthMetrics": true,
    "consensusMetrics": true,
    "storageMetrics": true,
    "customMetrics": false
  }
}

// Response
{
  "processMetrics": {
    "residentMemory": 1073741824,
    "virtualMemory": 2147483648,
    "cpuUsage": 15.5,
    "fdCount": 256
  },
  "connectionMetrics": {

    "rpcClients": 3
  },
  "bandwidthMetrics": {
    "bytesSent": 1048576000,
    "bytesReceived": 2097152000
  },

    "blocksSubmitted": 52340000,
    "headerCount": 52340000
  },

    "dbSize": 53687091200
  },
  "serverTime": 1700000000000
}
```

## Notes

- Metrics provide a comprehensive snapshot of the node's health and resource consumption.
- Use this for building monitoring dashboards, alerting systems, or capacity planning.
- The exact fields available may vary between node versions as new metrics are added.
- This is a heavier call than `GetInfo` or `GetConnections`; avoid polling at very high frequencies.

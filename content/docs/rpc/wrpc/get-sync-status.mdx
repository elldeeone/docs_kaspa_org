---
title: "GetSyncStatus"
description: "Check whether the node is fully synchronized with the Kaspa network."
---

## Request

No parameters required.

## Response

| Field | Type | Description |
|-------|------|-------------|
| `isSynced` | boolean | `true` when the node considers itself synced (recent sink timestamp, sufficient connectivity, and not in transitional IBD state). |

## Example

```json
// Request
{
  "method": "getSyncStatus",
  "params": {}
}

// Response
{
  "isSynced": true
}
```

## Notes

- Sync status is a readiness heuristic, not a literal proof that every possible block has been downloaded.
- During initial block download (IBD), this returns `false`.
- IBD duration depends on hardware, network conditions, and chain state history.
- Applications should check sync status before trusting balance or UTXO data from the node.
- This is the simplest way to check if a node is ready to serve accurate data.

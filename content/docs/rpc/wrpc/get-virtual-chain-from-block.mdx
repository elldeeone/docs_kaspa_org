---
title: "GetVirtualChainFromBlock"
description: "Get the virtual selected parent chain starting from a given block, including chain reorganization data."
---

## Request

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `startHash` | string | Yes | The hash of the block to start the chain traversal from. |
| `includeAcceptedTransactionIds` | boolean | No | Whether to include the IDs of accepted transactions for each chain block. |
| `minConfirmationCount` | u64 | No | Minimum number of confirmations required. Only chain blocks with at least this many confirmations are included. |

## Response

| Field | Type | Description |
|-------|------|-------------|
| `removedChainBlockHashes` | string[] | Blocks that were removed from the selected chain since `startHash` (due to reorg). |
| `addedChainBlockHashes` | string[] | Blocks that were added to the selected chain since `startHash`. |
| `acceptedTransactionIds` | object[] | For each added chain block, the list of accepted transaction IDs (only if requested). |

## Example

```json
// Request
{
  "method": "getVirtualChainFromBlock",
  "params": {
    "startHash": "6ef1913d30d5063e040839fcc67cbf02e8e0ae6e4a3cb774c7777043399697f5",
    "includeAcceptedTransactionIds": true
  }
}

// Response
{
  "removedChainBlockHashes": [],
  "addedChainBlockHashes": [
    "aabb1122...",
    "ccdd3344..."
  ],
  "acceptedTransactionIds": [
    {
      "acceptingBlockHash": "aabb1122...",
      "acceptedTransactionIds": ["tx1111...", "tx2222..."]
    }
  ]
}
```

## Notes

- This method is essential for tracking confirmed transactions. A transaction is considered confirmed when it appears in the `acceptedTransactionIds` of a chain block.
- The `removedChainBlockHashes` list is non-empty when a chain reorganization has occurred between the `startHash` and the current virtual.
- Use this method in combination with subscriptions to `VirtualChainChanged` for real-time transaction confirmation tracking.

<Callout>
If `removedChainBlockHashes` is non-empty, a chain reorg has occurred. Any transactions that were accepted by the removed blocks should be considered unconfirmed until they appear in the added chain blocks.
</Callout>

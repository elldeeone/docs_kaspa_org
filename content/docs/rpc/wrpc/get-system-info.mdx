---
title: "GetSystemInfo"
description: "Get system-level information about the node's host machine and build."
---

## Request

No parameters required.

## Response

| Field | Type | Description |
|-------|------|-------------|
| `version` | string | The node software version. |
| `systemId` | string \| number[] \| null | Machine/system identifier bytes (not per-node-instance state). Encoding is client/transport dependent. |
| `gitHash` | string \| number[] \| null | Build git hash bytes. Encoding is client/transport dependent. |
| `cpuPhysicalCores` | u16 | Number of physical CPU cores available to the node. |
| `totalMemory` | u64 | Total system memory in bytes. |
| `fdLimit` | u32 | The file descriptor limit for the process. |
| `proxySocketLimitPerCpuCore` | u32 \| null | The proxy socket limit per CPU core. Can be `null` if not applicable. |

## Example

```json
// Request
{
  "method": "getSystemInfo",
  "params": {}
}

// Response
{
  "version": "0.15.0",
  "systemId": "9f34...ab12",
  "gitHash": "7d8c...e0f1",
  "cpuPhysicalCores": 8,
  "totalMemory": 17179869184,
  "fdLimit": 65536,
  "proxySocketLimitPerCpuCore": null
}
```

## Notes

- This method is primarily useful for diagnostics and monitoring dashboards.
- `systemId` is derived from machine identity data (for example `/etc/machine-id` or MAC fallback), then hashed.
- The `gitHash` helps identify the exact build of the node software when reporting issues.
- A low `fdLimit` can cause connection issues on nodes with many peers. The minimum acceptable limit is `4096`, and `8192` is the desired soft limit.

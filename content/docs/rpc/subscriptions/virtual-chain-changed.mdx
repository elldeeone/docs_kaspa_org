## Overview

The virtual-chain-changed subscription notifies your application whenever the virtual selected parent chain changes. This includes both normal chain growth (new blocks appended) and reorganizations (blocks removed and replaced). It also optionally reports which transactions were accepted by each new chain block.

This is the primary subscription for applications that need to track transaction confirmations and detect chain reorganizations.

## Subscribe

```typescript
await rpc.subscribeVirtualChainChanged(true); // true = include accepted transaction IDs
```

**Wire contract note:** wRPC notification control uses `subscribe` / `unsubscribe` with a `VirtualChainChanged` scope payload (`includeAcceptedTransactionIds` flag). gRPC uses `NotifyVirtualChainChangedRequestMessage` with `includeAcceptedTransactionIds` and `command` set to `NOTIFY_START` or `NOTIFY_STOP`.

## Unsubscribe

```typescript
await rpc.unsubscribeVirtualChainChanged(true); // use the same includeAcceptedTransactionIds value used when subscribing
```

## Notification Format

```json
{
  "removedChainBlockHashes": [],
  "addedChainBlockHashes": [
    "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2"
  ],
  "acceptedTransactionIds": [
    {
      "acceptingBlockHash": "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2",
      "acceptedTransactionIds": [
        "1234567890abcdef1234567890abcdef1234567890abcdef1234567890abcdef",
        "fedcba0987654321fedcba0987654321fedcba0987654321fedcba0987654321"
      ]
    }
  ]
}
```

### Fields

| Field | Type | Description |
|---|---|---|
| `removedChainBlockHashes` | array | Blocks removed from the chain (non-empty during a reorg) |
| `addedChainBlockHashes` | array | Blocks added to the chain, in order |
| `acceptedTransactionIds` | array | Per-block list of accepted transaction IDs (if requested) |

## Event Handling

```typescript
rpc.addEventListener("virtual-chain-changed", (event) => {
  const { removedChainBlockHashes, addedChainBlockHashes, acceptedTransactionIds } = event.data;

  // Detect reorganizations
  if (removedChainBlockHashes.length > 0) {
    console.log(`Reorg detected: ${removedChainBlockHashes.length} blocks removed`);
    // Roll back any state derived from removed blocks
  }

  // Process new chain blocks
  for (const blockHash of addedChainBlockHashes) {
    console.log(`New chain block: ${blockHash}`);
  }

  // Track accepted transactions
  if (acceptedTransactionIds) {
    for (const entry of acceptedTransactionIds) {
      for (const txId of entry.acceptedTransactionIds) {
        console.log(`Transaction ${txId} accepted in ${entry.acceptingBlockHash}`);
      }
    }
  }
});
```

## Use Cases

- **Transaction confirmation tracking** -- Monitor when a specific transaction gets accepted in the virtual chain.
- **Exchange integrations** -- Detect deposits by watching for accepted transactions, and handle reorganizations by rolling back unconfirmed credits.
- **Block explorers** -- Track the canonical chain and display reorganization history.
- **Ledger synchronization** -- Keep an external database in sync with the virtual chain state.

<Callout type="info">
The `removedChainBlockHashes` array is empty during normal chain growth. Your application should always handle both arrays to remain correct under reorg conditions.
</Callout>

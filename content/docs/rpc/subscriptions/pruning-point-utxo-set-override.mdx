## Overview

The `notifyPruningPointUtxoSetOverride` subscription notifies your application when the node's pruning point UTXO set is replaced. This happens during initial block download (IBD) when a node syncs from a peer and receives a new pruning point UTXO set, or during certain rare reorganization scenarios.

The pruning point is the deepest block in the DAG that the node considers immutable. When the pruning point advances and the UTXO set is replaced, it represents a significant state change that applications maintaining local UTXO state need to be aware of.

## Subscribe

```typescript
await rpc.subscribePruningPointUtxoSetOverride();
```

**RPC request:**

```json
{
  "method": "notifyPruningPointUtxoSetOverride",
  "params": {}
}
```

## Unsubscribe

```typescript
await rpc.unsubscribePruningPointUtxoSetOverride();
```

## Notification Format

The notification signals that the pruning point UTXO set has been overridden. The notification body is empty -- it serves as a trigger for applications to refresh their local state.

```json
{}
```

## Event Handling

```typescript
rpc.addEventListener("pruning-point-utxo-set-override", async (event) => {
  console.log("Pruning point UTXO set has been overridden");

  // Refresh local UTXO state
  const dagInfo = await rpc.getBlockDagInfo();
  console.log(`New pruning point: ${dagInfo.pruningPointHash}`);

  // Re-query UTXOs for all watched addresses
  const utxos = await rpc.getUtxosByAddresses(myWatchedAddresses);
  rebuildLocalUtxoState(utxos);
});
```

## When This Occurs

- **Initial block download (IBD)** -- When a new node syncs for the first time, it receives the pruning point UTXO set from a peer. This notification fires once the set is loaded.
- **Pruning point advancement** -- As the DAG grows, the pruning point periodically advances. When this happens and the UTXO commitment changes, this notification fires.
- **Rare deep reorganizations** -- In extraordinary circumstances, a deep reorganization could cause the pruning point to shift.

<Callout type="info">
This notification is primarily relevant for applications that maintain their own copy of the UTXO set or depend on the pruning point for state anchoring. Most applications that only track specific addresses via `notifyUtxosChanged` do not need this subscription.
</Callout>

## Use Cases

- **Full UTXO set indexers** -- Rebuild the local UTXO index when the pruning point set is replaced.
- **Node monitoring** -- Detect when a node completes IBD or advances its pruning point.
- **State validation** -- Verify local state consistency after a pruning point change.

Running a Kaspa node in production requires careful attention to hardware, security, and operational reliability. This guide covers the key areas for a production deployment.

## Hardware Requirements

| Resource | Minimum | Recommended | Notes |
|---|---|---|---|
| CPU | 4 cores | 8+ cores | More cores help during initial sync |
| RAM | 8 GB | 16-32 GB | Adjust `--ram-scale` if constrained |
| Storage | 80+ GB (SSD or tuned HDD) | 200+ GB NVMe | HDD is possible with `--rocksdb-preset=hdd`, but slower |
| Network | 25 Mbps | 100+ Mbps | High peer counts increase bandwidth |

<Callout type="warn">
SSD/NVMe is strongly recommended for general production workloads. If you must run on HDD, use `--rocksdb-preset=hdd` and expect slower sync plus tighter operational margins.
</Callout>

## Firewall Configuration

Expose only the ports you need:

```bash
sudo ufw allow 16111/tcp comment "Kaspa P2P mainnet"
# Only if serving external clients:
sudo ufw allow 16110/tcp comment "Kaspa gRPC mainnet"
sudo ufw enable
```

| Port | Purpose | Exposure |
|---|---|---|
| 16111 | P2P gossip | Public (required) |
| 16110 | gRPC | Restrict to trusted IPs |

<Callout type="info">
If your node only serves local applications, bind gRPC to localhost: `--rpclisten=127.0.0.1:16110`. For wRPC (WebSocket) access, use `--rpclisten-borsh=127.0.0.1:17110`. Never expose RPC to the public internet without authentication.
</Callout>

## Systemd Service

```ini
# /etc/systemd/system/kaspad.service
[Unit]
Description=Kaspa Node (rusty-kaspa)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=kaspa
Group=kaspa
ExecStart=/usr/local/bin/kaspad \
  --utxoindex \
  --rpclisten=127.0.0.1:16110 \
  --listen=0.0.0.0:16111 \
  --appdir=/var/lib/kaspa \
  --perf-metrics \
  --ram-scale=0.8
Restart=on-failure
RestartSec=10
LimitNOFILE=65536
NoNewPrivileges=yes

[Install]
WantedBy=multi-user.target
```

```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin kaspa
sudo mkdir -p /var/lib/kaspa && sudo chown kaspa:kaspa /var/lib/kaspa
sudo systemctl daemon-reload && sudo systemctl enable --now kaspad
```

## Performance Tuning

| RAM Available | Recommended `--ram-scale` |
|---|---|
| 8 GB | 0.3-0.5 |
| 16 GB | 1.0 (default) |
| 32 GB+ | 2.0-3.0 |

Mount storage with `noatime` to reduce unnecessary write operations. Use NVMe over SATA for best RocksDB performance.

## Log Management

Configure log rotation to prevent disk exhaustion:

```ini
# /etc/logrotate.d/kaspad
/var/lib/kaspa/logs/*.log {
    daily
    rotate 14
    compress
    missingok
    notifempty
    copytruncate
}
```

Alternatively, run with `--nologfiles` and rely on journald.

## Backup Strategy

| Component | Backup method | Frequency |
|---|---|---|
| Configuration | Version control | On change |
| Data directory | Filesystem snapshot (LVM/ZFS) | Daily |
| Wallet mnemonic | Encrypted offline backup | Once (at creation) |

<Callout type="info">
You do not need to back up blockchain data for recoverability. Re-sync time is environment-dependent (hardware, network, and current DAG size). Backing up the data directory mainly reduces recovery time.
</Callout>

## Security Checklist

- Run kaspad as a non-root, dedicated system user
- Bind wRPC to `127.0.0.1` unless remote access is required
- Keep the OS and rusty-kaspa updated
- Use SSH key authentication; disable password login
- Set `LimitNOFILE=65536` in the systemd unit
- Monitor logs for `[ERR]` entries and investigate promptly

## Overview

Kaspa is a proof-of-work (PoW) cryptocurrency secured by the same fundamental assumption as Bitcoin: the majority of mining hashrate is controlled by honest participants. However, Kaspa's BlockDAG structure and GHOSTDAG consensus protocol introduce important differences in how security is achieved and what guarantees it provides.

## Proof-of-Work Security

Kaspa uses the **kHeavyHash** proof-of-work algorithm. Miners must find a block hash below a target value, which requires expending real-world energy (computation). This energy expenditure is what gives the network its security — to reverse confirmed transactions, an attacker must outpace the cumulative hashrate of the honest network.

The security of any PoW system rests on the **honest majority assumption**: as long as more than 50% of the network's hashrate is controlled by honest miners, the protocol guarantees that:

- Confirmed transactions will not be reversed.
- The selected parent chain will reflect the honest majority's view of block ordering.
- Double-spend attacks will fail.

## 51% Attack Resistance in a DAG

In a traditional blockchain, a 51% attacker can create a secret chain longer than the honest chain and release it to reverse transactions. In Kaspa's DAG, the situation is more nuanced:

- **Parallel blocks are included**: The DAG includes all blocks, not just those on a single chain. An attacker cannot simply "orphan" honest blocks — they become part of the DAG structure.
- **GHOSTDAG voting**: GHOSTDAG uses the DAG's structure to identify which blocks are "blue" (honest) and which are "red" (adversarial). A block that is well-connected to the majority of recent blocks is more likely to be blue.
- **Higher threshold in practice**: Because honest blocks are incorporated into the DAG rather than orphaned, the effective threshold for a successful attack is higher than in a simple longest-chain system.

<Callout type="info">
In a blockchain, honest blocks that lose the race are orphaned and wasted. In Kaspa's DAG, honest blocks are still included and contribute to the security of the selected parent chain. This improves both security and miner fairness.
</Callout>

## The k Parameter

The **k parameter** is central to GHOSTDAG security. It defines the maximum number of parallel blocks that can exist simultaneously under honest network conditions. The value of k is calculated from:

- **Block rate**: 10 blocks per second.
- **Network propagation delay (D)**: Assumed to be 5 seconds maximum.
- **Probability bound**: The chance that an honest block has more than k parallel blocks is kept negligibly small.

With these parameters, k is set to **124** on mainnet (post-Crescendo at 10 BPS). This means GHOSTDAG expects at most 124 honest blocks to be created during one propagation delay period. The value is derived from the Poisson distribution with `x = 2Dλ = 2 × 5 × 10 = 100`, yielding K=124 at a 1% tolerance. Any block with more than k blocks in its anticone (blocks neither in its past nor future) is classified as red.

## Network Delay Assumptions

Kaspa's security analysis assumes a maximum network propagation delay **D = 5 seconds**. This means:

- A block produced by an honest miner should reach all other honest miners within 5 seconds.
- If the actual propagation delay exceeds this assumption, some honest blocks may be incorrectly classified as red, but the protocol remains safe (it just becomes less efficient).
- The k parameter provides a buffer — honest blocks are classified as blue even if they are produced in parallel, as long as the number of parallel blocks stays within k.

<Callout type="warn">
If you are running a mining operation, ensure your node has good network connectivity. High latency increases the chance of your blocks being classified as red, which means you lose the block reward.
</Callout>

## Confirmation Depth and Probability of Reversal

The probability that a confirmed transaction is reversed decreases exponentially with confirmation depth (measured in blue score). For a given attacker hashrate share `q` (where `q < 0.5`), the probability of reversing a transaction with `d` confirmations is approximately:

```
P(reversal) ≈ (q / (1-q))^d
```

This exponential decay means:

| Attacker hashrate | Depth for < 0.1% reversal probability |
|---|---|
| 10% | ~7 blue score |
| 20% | ~14 blue score |
| 30% | ~25 blue score |
| 40% | ~72 blue score |
| 49% | ~920 blue score |

At Kaspa's 10 BPS rate, even conservative confirmation depths are reached in seconds.

## Finality Depth

Kaspa defines a **finality depth** of **432,000 blue score** (approximately 12 hours at 10 BPS). After this depth:

- The pruning mechanism removes old block data below the finality point.
- Transactions below the finality depth are considered irreversible by all nodes.
- Reorgs deeper than the finality depth are rejected by the protocol, even if an attacker presents a heavier chain.

This provides a hard finality guarantee that does not exist in Bitcoin (where, in theory, arbitrarily deep reorgs are possible if an attacker has sufficient hashrate).

<Callout>
The finality depth of 432,000 blue score provides a strong guarantee: once a transaction is buried this deep, it cannot be reversed even by an attacker with majority hashrate. This is a stronger guarantee than Bitcoin's probabilistic finality.
</Callout>

## GHOSTDAG Security Analysis

GHOSTDAG has been formally analyzed in the academic literature. The key results are:

- **Liveness**: The protocol continues to confirm transactions as long as the network is operational, even in the presence of adversarial blocks.
- **Safety**: Transactions confirmed with sufficient depth are not reversed under the honest majority assumption.
- **Fairness**: Honest miners' blocks are included in the DAG and rewarded, regardless of whether they were produced in parallel with other blocks.

The DAG structure allows high throughput (10 BPS) without sacrificing security, because parallel blocks are included rather than orphaned.

## Comparison with Blockchain Security

| Property | Kaspa (DAG) | Bitcoin (Blockchain) |
|---|---|---|
| Honest block inclusion | All honest blocks included | Only one block per height survives |
| Orphan rate | Near zero (blocks are merged) | Increases with block rate |
| Confirmation time | Seconds | Minutes to hours |
| Finality | Hard finality at 432,000 blue score | Probabilistic only |
| Attack threshold | >50% hashrate (enhanced by DAG) | >50% hashrate |
| Throughput | 10 BPS without security loss | ~1 block/600 seconds |

## Practical Security Recommendations

For different transaction values, consider these confirmation depth guidelines:

- **Casual transactions** (small amounts): 10-100 blue score (1-10 seconds). Sufficient for everyday purchases.
- **Significant transactions** (moderate amounts): 1,000 blue score (~100 seconds). Appropriate for most commercial transactions.
- **Large transactions** (high-value transfers): 10,000+ blue score (~17 minutes). Provides very strong assurance.
- **Critical or irreversible decisions**: Wait for finality depth (432,000 blue score, ~12 hours). Recommended for exchange deposits of very large amounts.

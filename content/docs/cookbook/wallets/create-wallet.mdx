## Prerequisites

- **Kaspa WASM SDK** installed (`npm install kaspa-wasm`)

<Callout>
A Kaspa wallet is derived from a **24-word mnemonic seed phrase** following BIP-39. This phrase is the master backup for the entire wallet -- all addresses and keys can be regenerated from it. Store it securely offline and never share it.
</Callout>

## Code

The following example generates a new wallet from scratch, derives the master key, and produces the first receive address:

```typescript
import {
  Mnemonic,
  XPrv,
  XPub,
  PrivateKey,
  PublicKey,
  Address,
} from "kaspa-wasm";

function createWallet(network: string = "mainnet") {
  // 1. Generate a random 24-word mnemonic
  const mnemonic = Mnemonic.random(24);
  console.log("Seed phrase (BACK THIS UP SECURELY):");
  console.log(mnemonic.phrase);
  console.log();

  // 2. Derive the HD master seed
  //    The passphrase parameter adds an optional extra layer of protection.
  //    Use an empty string if you do not want a passphrase.
  const passphrase = "";
  const seed = mnemonic.toSeed(passphrase);

  // 3. Create the extended private key (master key)
  const xprv = new XPrv(seed);

  // 4. Derive the Kaspa account key using the standard path
  //    m/44' = BIP-44 purpose
  //    /111111' = Kaspa coin type
  //    /0' = first account
  const accountKey = xprv.derivePath("m/44'/111111'/0'");

  // 5. Derive the first receive address key (external chain, index 0)
  const receiveKey = accountKey.derivePath("0/0");
  const receivePrivateKey = receiveKey.toPrivateKey();
  const receivePublicKey = receivePrivateKey.toPublicKey();
  const receiveAddress = receivePublicKey.toAddress(network);

  console.log("First receive address:", receiveAddress.toString());
  console.log("Public key:", receivePublicKey.toString());

  // 6. Derive the first change address key (internal chain, index 0)
  const changeKey = accountKey.derivePath("1/0");
  const changePrivateKey = changeKey.toPrivateKey();
  const changeAddress = changePrivateKey.toPublicKey().toAddress(network);

  console.log("First change address:", changeAddress.toString());

  // 7. Derive the extended public key for watch-only use
  //    The xpub can generate addresses without access to private keys
  const accountXPub = accountKey.toXPub();
  console.log("\nExtended public key (for watch-only wallets):");
  console.log(accountXPub.toString());

  return {
    mnemonic: mnemonic.phrase,
    receiveAddress: receiveAddress.toString(),
    changeAddress: changeAddress.toString(),
    xpub: accountXPub.toString(),
  };
}

// Generate a mainnet wallet
const wallet = createWallet("mainnet");

// For testnet development, use:
// const testWallet = createWallet("testnet-10");
```

## Explanation

### Mnemonic generation

`Mnemonic.random(24)` generates a cryptographically secure random 24-word phrase following the BIP-39 standard. The 24 words encode 256 bits of entropy plus a checksum. You can also generate a 12-word mnemonic with `Mnemonic.random(12)` for 128 bits of entropy, though 24 words is recommended for maximum security.

### Derivation path

Kaspa uses the BIP-44 hierarchical deterministic derivation standard:

```
m / 44' / 111111' / account' / chain / index
```

| Level | Value | Meaning |
|---|---|---|
| Purpose | `44'` | BIP-44 multi-account hierarchy |
| Coin type | `111111'` | Kaspa's registered coin type |
| Account | `0'` | First account (increment for multiple accounts) |
| Chain | `0` | External (receive) addresses |
| Chain | `1` | Internal (change) addresses |
| Index | `0, 1, 2...` | Sequential address index |

The apostrophe (`'`) denotes hardened derivation, which prevents child keys from being used to derive the parent key.

### Receive vs. change addresses

- **Receive addresses** (chain `0`) are given to others for incoming payments
- **Change addresses** (chain `1`) are used internally to receive leftover funds when a UTXO is partially spent

This separation improves privacy by making it harder for observers to determine which output is the payment and which is change.

### Extended public keys

The `XPub` (extended public key) can derive all public keys and addresses for the account without access to private keys. This is useful for:

- **Watch-only wallets** that track balances without spending capability
- **Payment servers** that generate unique addresses for each customer
- **Auditing** systems that monitor wallet activity

<Callout type="info">
Never store the mnemonic phrase or private keys in plaintext in your application code, environment variables, or databases. Use secure key management systems, hardware security modules, or encrypted storage. The examples in this recipe use inline values for clarity only.
</Callout>

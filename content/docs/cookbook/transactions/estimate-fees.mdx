## Prerequisites

- **Kaspa WASM SDK** installed (`npm install kaspa-wasm`)
- **Connection to a Kaspa node** with an active `RpcClient`

<Callout type="info">
Kaspa transaction fees are calculated as `fee_rate x transaction_mass`. The mass is a multi-dimensional metric that accounts for compute cost (signature verification), bandwidth (serialized size), and UTXO storage impact. See [Fees and Mass](/docs/core-concepts/fees-and-mass) for the full breakdown.
</Callout>

## Code

The following example demonstrates how to query fee estimates from a Kaspa node and calculate the total fee for a transaction:

```typescript
import {
  RpcClient,
  Resolver,
  Encoding,
  UtxoProcessor,
  UtxoContext,
  createTransactions,
  kaspaToSompi,
} from "kaspa-wasm";

async function estimateFees() {
  // 1. Connect to a Kaspa node
  const rpc = new RpcClient({
    resolver: new Resolver(),
    encoding: Encoding.Borsh,
    networkId: "mainnet",
  });
  await rpc.connect();

  // 2. Retrieve fee estimates from the node
  const feeEstimate = await rpc.getFeeEstimate();
  const estimate = feeEstimate.estimate;
  console.log("Fee estimate buckets:");
  console.log("  Priority:", estimate.priorityBucket);
  console.log("  Normal:", estimate.normalBuckets);
  console.log("  Low:", estimate.lowBuckets);

  // 3. For more detailed estimates with bucket breakdowns
  const detailedEstimate = await rpc.getFeeEstimateExperimental({
    verbose: true,
  });
  console.log("Detailed estimate:", detailedEstimate);

  // 4. Calculate total fee for a specific transaction
  // Set up UTXO tracking for the sender
  const processor = new UtxoProcessor({ rpc, networkId: "mainnet" });
  const context = new UtxoContext({ processor });
  await processor.start();

  const senderAddress = "kaspa:qr35ennsep3hxfe7lnz5ee7j5jgmkjswsn27efrq0";
  await context.trackAddresses([senderAddress]);
  await new Promise((resolve) => setTimeout(resolve, 3000));

  // Build the transaction to determine its mass
  const { transactions, summary } = await createTransactions({
    entries: context,
    outputs: [
      {
        address: "kaspa:qzk3uh2twist37c03lttcxldrj2muple9taq065u0d",
        amount: kaspaToSompi("5.0"),
      },
    ],
    changeAddress: senderAddress,
    priorityFee: 0n,
  });

  // 5. Read the mass and compute fees at each priority level
  const priorityFeeRate = estimate.priorityBucket.feerate;

  console.log("\nTransaction details:");
  console.log("  Number of transactions:", transactions.length);
  console.log("  Summary:", summary);

  // Estimate what the fee would be at priority rate
  console.log("\nEstimated fees:");
  console.log(
    "  At priority rate (" + priorityFeeRate + " sompi/mass):",
    "Use priorityFee parameter in createTransactions"
  );

  // 6. Rebuild with a priority fee to ensure fast confirmation
  const { transactions: priorityTxs, summary: prioritySummary } =
    await createTransactions({
      entries: context,
      outputs: [
        {
          address: "kaspa:qzk3uh2twist37c03lttcxldrj2muple9taq065u0d",
          amount: kaspaToSompi("5.0"),
        },
      ],
      changeAddress: senderAddress,
      priorityFee: kaspaToSompi("0.0001"), // Small priority fee boost
    });

  console.log("Priority transaction summary:", prioritySummary);

  // Clean up
  await processor.stop();
  await rpc.disconnect();
}

estimateFees().catch(console.error);
```

## Explanation

### Fee estimate buckets

The `getFeeEstimate` RPC method returns a response with a top-level `estimate` field containing fee rate recommendations organized into priority tiers:

| Bucket | Meaning |
|---|---|
| **Priority** | Higher suggested fee-rate bucket from the node estimator. |
| **Normal** | Mid-range fee-rate buckets from the node estimator. |
| **Low** | Lower fee-rate buckets for less time-sensitive transactions. |

Each bucket contains a `feerate` value in sompi per mass unit. The total fee for a transaction is:

```
total_fee = feerate x transaction_mass
```

### The experimental endpoint

`getFeeEstimateExperimental` provides additional estimator detail (shape may vary by node version). This is useful for building UIs that expose fee-rate choices.

### How createTransactions handles fees

The `createTransactions` function computes the minimum required fee automatically based on the transaction mass. The `priorityFee` parameter adds an extra fee on top of the minimum to boost inclusion priority. When `priorityFee` is `0n`, the transaction pays only the minimum relay fee.

<Callout>
Actual inclusion speed depends on current mempool conditions. Treat fee estimates as dynamic network signals rather than fixed guarantees.
</Callout>

### Mass components

Mass is determined by three components:

- **Compute mass**: Signature/script verification cost.
- **Transactional mass**: Serialized transaction size cost.
- **Storage mass**: UTXO set impact (see KIP-9).

The effective mass is the maximum of these components for a given transaction.

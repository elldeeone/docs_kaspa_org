## Prerequisites

- **A running Kaspa node** with gRPC enabled (default port 16110)
- **gRPC client library** for your language (e.g., `@grpc/grpc-js` for Node.js)
- **Kaspa protobuf definitions** from the [rusty-kaspa repository](https://github.com/kaspanet/rusty-kaspa)

<Callout type="info">
gRPC is an alternative to wRPC for communicating with Kaspa nodes. While wRPC (WebSocket) is the recommended protocol for the WASM SDK and browser applications, gRPC is useful for server-side applications in languages like Go, Python, or Java that have mature gRPC ecosystems.
</Callout>

## Code

The following example demonstrates connecting to a Kaspa node over gRPC using Node.js:

```typescript
import * as grpc from "@grpc/grpc-js";
import * as protoLoader from "@grpc/proto-loader";
import path from "path";

// 1. Load the Kaspa protobuf definitions
const PROTO_PATH = path.resolve(__dirname, "proto/messages.proto");

const packageDefinition = protoLoader.loadSync(PROTO_PATH, {
  keepCase: true,
  longs: String,
  enums: String,
  defaults: true,
  oneofs: true,
});

const kaspaProto = grpc.loadPackageDefinition(packageDefinition) as any;

// 2. Create a gRPC client
function createClient(host: string = "127.0.0.1:16110") {
  const client = new kaspaProto.protowire.RPC(
    host,
    grpc.credentials.createInsecure()
  );

  return client;
}

// 3. Make RPC calls using the bidirectional message stream
async function connectAndQuery(host: string = "127.0.0.1:16110") {
  const client = createClient(host);

  // Kaspa gRPC uses a single bidirectional stream for all messages
  const stream = client.MessageStream();

  // Set up message handler
  stream.on("data", (response: any) => {
    // Route responses based on which field is populated
    if (response.getBlockDagInfoResponse) {
      const info = response.getBlockDagInfoResponse;
      console.log("Network:", info.networkName);
      console.log("Block count:", info.blockCount);
      console.log("DAA score:", info.virtualDaaScore);
      console.log("Difficulty:", info.difficulty);
    }

    if (response.getInfoResponse) {
      const info = response.getInfoResponse;
      console.log("Server version:", info.serverVersion);
      console.log("Is synced:", info.isSynced);
      console.log("Is UTXO indexed:", info.isUtxoIndexed);
    }

    if (response.notifyBlockAddedResponse) {
      console.log("Subscribed to block notifications");
    }

    if (response.blockAddedNotification) {
      const block = response.blockAddedNotification.block;
      console.log("New block:", block.header.hash);
    }

    if (response.getBalanceByAddressResponse) {
      const balance = response.getBalanceByAddressResponse.balance;
      console.log("Balance:", balance, "sompi");
    }
  });

  stream.on("error", (err: Error) => {
    console.error("Stream error:", err.message);
  });

  stream.on("end", () => {
    console.log("Stream ended");
  });

  // 4. Send RPC requests through the stream
  // Get DAG info
  stream.write({
    getBlockDagInfoRequest: {},
  });

  // Get node info
  stream.write({
    getInfoRequest: {},
  });

  // Get balance for an address
  stream.write({
    getBalanceByAddressRequest: {
      address: "kaspa:qr35ennsep3hxfe7lnz5ee7j5jgmkjswsn27efrq0",
    },
  });

  // Subscribe to new blocks
  stream.write({
    notifyBlockAddedRequest: {
      command: 0, // 0 = start notification
    },
  });

  // Keep the connection alive
  return { client, stream };
}

// 5. Helper: Promise-based RPC call
function rpcCall(stream: any, request: object): Promise<any> {
  return new Promise((resolve, reject) => {
    const timeout = setTimeout(() => {
      reject(new Error("RPC call timed out"));
    }, 10000);

    const handler = (response: any) => {
      clearTimeout(timeout);
      stream.removeListener("data", handler);
      resolve(response);
    };

    stream.on("data", handler);
    stream.write(request);
  });
}

// Usage
async function main() {
  console.log("Connecting to Kaspa node via gRPC...");
  const { client, stream } = await connectAndQuery("127.0.0.1:16110");

  // Wait for responses
  await new Promise((resolve) => setTimeout(resolve, 5000));

  // Close the stream
  stream.end();
  client.close();
}

main().catch(console.error);
```

## Explanation

### gRPC vs. wRPC

| Feature | gRPC | wRPC |
|---|---|---|
| Transport | HTTP/2 | WebSocket |
| Encoding | Protobuf | Borsh or JSON |
| Browser support | No (requires proxy) | Yes (native WebSocket) |
| Language support | Many (Go, Python, Java, C++, etc.) | JavaScript/TypeScript via WASM SDK |
| Streaming | Bidirectional | Bidirectional |
| Default port (mainnet) | 16110 | 17110 (Borsh), 18110 (JSON) |

### Kaspa's gRPC message pattern

Kaspa uses a single bidirectional gRPC stream (`MessageStream`) for all RPC communication. Unlike typical gRPC services with separate methods per operation, all requests and responses flow through the same stream. Each message is a oneof containing one request or response type.

This design means:

- You write request messages to the stream
- You read response messages from the stream
- You must match responses to requests yourself (e.g., by checking which response field is populated)
- Subscription notifications arrive on the same stream

### Protobuf definitions

The Kaspa protobuf definitions are maintained in the `rusty-kaspa` repository under the `rpc/grpc/proto` directory. You need these `.proto` files to generate client code for your language.

<Callout>
The gRPC interface mirrors the same RPC methods available through wRPC. The method names and parameters are equivalent; only the transport and serialization differ. See the [RPC API Reference](/docs/reference/api-reference) for the complete list of available methods.
</Callout>

### When to use gRPC

- **Server-side applications** in languages other than JavaScript/TypeScript
- **Existing infrastructure** that already uses gRPC (e.g., Go microservices)
- **Environments** where WebSocket support is limited

### When to use wRPC instead

- **Browser applications** (gRPC requires HTTP/2, which browsers do not expose directly)
- **JavaScript/TypeScript projects** (the WASM SDK provides a much simpler API)
- **New projects** without existing gRPC infrastructure

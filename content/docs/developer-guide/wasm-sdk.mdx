The Kaspa WASM SDK provides a comprehensive toolkit for building Kaspa applications in JavaScript and TypeScript. Compiled from the Rust codebase to WebAssembly, it brings near-native performance to both browser and Node.js environments while exposing an idiomatic JavaScript API.

## Installation

The Kaspa WASM SDK is published as an npm package. Install it in your project:

```bash
npm install kaspa-wasm
```

<Callout type="info">
The package name and availability may vary. Check the [rusty-kaspa repository](https://github.com/kaspanet/rusty-kaspa) for the latest package name and installation instructions. The SDK may also be available under `kaspa` or other package names depending on the release channel.
</Callout>

### Browser Setup

For browser applications, you need to initialize the WASM module before using any SDK functionality:

```typescript
import kaspa from 'kaspa-wasm';

async function main() {
  // Initialize the WASM module
  await kaspa.default();

  // Now you can use all SDK classes
  const { RpcClient, Encoding, PrivateKey } = kaspa;
}

main();
```

### Node.js Setup

In Node.js, the WASM module loads synchronously:

```typescript
const kaspa = require('kaspa-wasm');

// Classes are available immediately in Node.js
const { RpcClient, Encoding, PrivateKey, Address } = kaspa;
```

## Core Classes

### RpcClient

The `RpcClient` class provides a high-level interface for communicating with Kaspa nodes via wRPC (WebSocket RPC). It handles connection management, serialization, and automatic reconnection.

```typescript
import { RpcClient, Encoding, Resolver } from 'kaspa-wasm';

// Connect using the built-in resolver (discovers public nodes automatically)
const rpc = new RpcClient({
  resolver: new Resolver(),
  encoding: Encoding.Borsh,
  networkId: "mainnet",
});

// Or connect directly to a specific node
const rpcDirect = new RpcClient({
  url: "ws://127.0.0.1:16110",
  encoding: Encoding.Borsh,
});

// Connect to the node
await rpc.connect();

// Check connection status
console.log("Connected:", rpc.isConnected);

// Query blockchain info
const dagInfo = await rpc.getBlockDagInfo();
console.log("Network:", dagInfo.networkName);
console.log("Block count:", dagInfo.blockCount);
console.log("Virtual DAA score:", dagInfo.virtualDaaScore);

// Get balance for an address
const balance = await rpc.getBalanceByAddress({
  address: "kaspa:qr35ennsep3hxfe7lnz5ee7j5jgmkjswsn35ennsep3hxfe7lkaspadev"
});
console.log("Balance:", balance.balance, "sompi");

// Disconnect when done
await rpc.disconnect();
```

### PrivateKey and PublicKey

Generate and manage Kaspa key pairs for signing transactions.

```typescript
import { PrivateKey } from 'kaspa-wasm';

// Generate a new random private key
const privateKey = new PrivateKey();
console.log("Private key (hex):", privateKey.toString());

// Or create from an existing hex string
const importedKey = new PrivateKey("your-64-char-hex-private-key-here");

// Derive the public key
const publicKey = privateKey.toPublicKey();
console.log("Public key:", publicKey.toString());

// Derive a Kaspa address from the public key
const address = publicKey.toAddress("mainnet");
console.log("Address:", address.toString());
// Output: kaspa:qr35ennsep3hxfe7lnz5ee7j5jgmkjswsn35ennsep3hxfe7lkaspadev
```

### Address

The `Address` class handles Kaspa address encoding and validation. Kaspa uses a Bech32 address format with a `kaspa:` prefix.

```typescript
import { Address } from 'kaspa-wasm';

// Parse an address string
const address = new Address("kaspa:qr35ennsep3hxfe7lnz5ee7j5jgmkjswsn35ennsep3hxfe7lkaspadev");

// Validate an address
console.log("Valid:", address.validate());
console.log("Network:", address.prefix); // "kaspa" for mainnet
console.log("Version:", address.version);

// Convert back to string
console.log("Address:", address.toString());
```

<Callout type="info">
Kaspa addresses use the Bech32 encoding scheme. Mainnet addresses have the `kaspa:` prefix, testnet addresses use `kaspatest:`, and simnet addresses use `kaspasim:`.
</Callout>

### UtxoProcessor

The `UtxoProcessor` manages UTXO tracking and transaction processing. It connects to an `RpcClient` and monitors UTXOs for registered addresses, keeping a local cache of available outputs for spending.

```typescript
import { RpcClient, UtxoProcessor, UtxoContext, Resolver, Encoding } from 'kaspa-wasm';

// Set up the RPC client
const rpc = new RpcClient({
  resolver: new Resolver(),
  encoding: Encoding.Borsh,
  networkId: "mainnet",
});
await rpc.connect();

// Create a UTXO processor bound to the RPC client
const processor = new UtxoProcessor({ rpc, networkId: "mainnet" });

// Create a UTXO context for tracking a set of addresses
const context = new UtxoContext({ processor });

// Start the processor (begins tracking UTXOs)
await processor.start();

// Register addresses to track
await context.trackAddresses([
  "kaspa:qr35ennsep3hxfe7lnz5ee7j5jgmkjswsn35ennsep3hxfe7lkaspadev"
]);

// Listen for balance changes
processor.addEventListener("balance", (event) => {
  console.log("Balance changed!");
  console.log("Mature balance:", context.balance?.mature);
  console.log("Pending balance:", context.balance?.pending);
});

// The processor now automatically tracks UTXOs and balance
// for the registered addresses
```

## Creating and Sending Transactions

Building transactions in Kaspa involves selecting UTXOs, constructing outputs, calculating fees, and signing. The WASM SDK provides utilities to simplify this process.

### Simple Transfer

```typescript
import {
  RpcClient,
  UtxoProcessor,
  UtxoContext,
  PrivateKey,
  Address,
  Resolver,
  Encoding,
  createTransactions,
  kaspaToSompi,
} from 'kaspa-wasm';

async function sendKaspa() {
  // Initialize RPC connection
  const rpc = new RpcClient({
    resolver: new Resolver(),
    encoding: Encoding.Borsh,
    networkId: "mainnet",
  });
  await rpc.connect();

  // Set up UTXO tracking
  const processor = new UtxoProcessor({ rpc, networkId: "mainnet" });
  const context = new UtxoContext({ processor });
  await processor.start();

  // Your private key (keep this secret!)
  const privateKey = new PrivateKey("your-private-key-hex");
  const senderAddress = privateKey.toPublicKey().toAddress("mainnet");

  // Track the sender address
  await context.trackAddresses([senderAddress.toString()]);

  // Wait for UTXO sync to complete
  // In production, listen for the 'balance' event
  await new Promise(resolve => setTimeout(resolve, 3000));

  // Define the recipient and amount
  const recipientAddress = "kaspa:recipient-address-here";
  const amountInSompi = kaspaToSompi(1.5); // Send 1.5 KAS

  // Create the transaction(s)
  // The SDK handles UTXO selection and change output automatically
  const { transactions, summary } = await createTransactions({
    entries: context,
    outputs: [
      {
        address: recipientAddress,
        amount: amountInSompi,
      },
    ],
    changeAddress: senderAddress.toString(),
    priorityFee: 0n, // Optional priority fee in sompi
  });

  // Sign and submit each transaction
  // (large transfers may produce multiple chained transactions)
  for (const tx of transactions) {
    tx.sign([privateKey]);
    const txId = await tx.submit(rpc);
    console.log("Transaction submitted:", txId);
  }

  console.log("Transfer complete!");
  console.log("Summary:", summary);

  // Clean up
  await processor.stop();
  await rpc.disconnect();
}

sendKaspa().catch(console.error);
```

<Callout type="warn">
Never hardcode private keys in your source code or commit them to version control. Use environment variables, secure key management systems, or prompt the user for their key at runtime.
</Callout>

### Understanding Transaction Chaining

In the UTXO model, each transaction consumes entire UTXOs as inputs. If a wallet has many small UTXOs (e.g., from frequent mining rewards), sending a large amount may require consuming more UTXOs than can fit in a single transaction. The `createTransactions` function handles this automatically by creating a chain of compound transactions:

1. **Compound transactions** consolidate many small UTXOs into fewer, larger UTXOs.
2. **The final transaction** sends the desired amount to the recipient with a change output back to the sender.

```typescript
// The createTransactions function returns an array of transactions
// that must be signed and submitted in order
const { transactions } = await createTransactions({
  entries: context,
  outputs: [{ address: recipient, amount: amountInSompi }],
  changeAddress: senderAddress.toString(),
});

console.log(`Transaction chain length: ${transactions.length}`);
// If length > 1, compound transactions are needed

for (const tx of transactions) {
  tx.sign([privateKey]);
  const txId = await tx.submit(rpc);
  console.log(`Submitted: ${txId}`);
  // Each transaction must be accepted before the next can be submitted
}
```

## Event Handling and Subscriptions

The WASM SDK provides an event-driven API for reacting to blockchain changes in real time.

### Listening for New Blocks

```typescript
const rpc = new RpcClient({
  resolver: new Resolver(),
  encoding: Encoding.Borsh,
  networkId: "mainnet",
});
await rpc.connect();

// Subscribe to block-added notifications
await rpc.subscribeBlockAdded();

rpc.addEventListener("block-added", (event) => {
  const block = event.data.block;
  console.log("New block:", block.header.hash);
  console.log("Blue score:", block.header.blueScore);
  console.log("Transactions:", block.transactions?.length ?? 0);
});
```

### Watching Address Activity

```typescript
// Subscribe to UTXO changes for specific addresses
await rpc.subscribeUtxosChanged([
  "kaspa:qr35ennsep3hxfe7lnz5ee7j5jgmkjswsn35ennsep3hxfe7lkaspadev"
]);

rpc.addEventListener("utxos-changed", (event) => {
  const { added, removed } = event.data;

  for (const entry of added) {
    console.log(`Received ${entry.utxoEntry.amount} sompi`);
    console.log(`In transaction: ${entry.outpoint.transactionId}`);
  }

  for (const entry of removed) {
    console.log(`Spent ${entry.utxoEntry.amount} sompi`);
  }
});
```

### Monitoring DAA Score

```typescript
await rpc.subscribeVirtualDaaScoreChanged();

rpc.addEventListener("virtual-daa-score-changed", (event) => {
  console.log("New DAA score:", event.data.virtualDaaScore);
});
```

## HD Wallet Support

The WASM SDK supports BIP-32 hierarchical deterministic (HD) wallets for generating multiple addresses from a single seed phrase.

```typescript
import { Mnemonic, XPrv } from 'kaspa-wasm';

// Generate a new 24-word mnemonic
const mnemonic = Mnemonic.random(24);
console.log("Seed phrase:", mnemonic.phrase);

// Derive the master extended private key
const seed = mnemonic.toSeed("");
const xprv = new XPrv(seed);

// Derive child keys using the Kaspa derivation path
// m/44'/111111'/0'/0/index
const accountKey = xprv
  .derivePath("m/44'/111111'/0'");

const receiveKey0 = accountKey.derivePath("0/0");
const receiveKey1 = accountKey.derivePath("0/1");
const changeKey0 = accountKey.derivePath("1/0");

// Get addresses from derived keys
const address0 = receiveKey0
  .toPrivateKey()
  .toPublicKey()
  .toAddress("mainnet");
console.log("Address 0:", address0.toString());
```

<Callout type="warn">
Store mnemonic seed phrases securely. Anyone with the seed phrase can derive all private keys and access all funds. Never transmit or store seed phrases in plaintext.
</Callout>

## Connecting to Public Nodes

The WASM SDK includes a `Resolver` class that discovers available public Kaspa nodes automatically. This is convenient for development and light client applications.

```typescript
import { Resolver } from 'kaspa-wasm';

// The resolver discovers public nodes for the specified network
const resolver = new Resolver();

// Use the resolver with RpcClient
const rpc = new RpcClient({
  resolver,
  encoding: Encoding.Borsh,
  networkId: "mainnet", // or "testnet-10", "testnet-11"
});

await rpc.connect();
// The resolver automatically selects an available node
```

<Callout type="info">
Public nodes are provided for convenience and development purposes. For production applications processing real value, always run your own Kaspa node to ensure reliability and security.
</Callout>

## TypeScript Support

The WASM SDK includes TypeScript type definitions out of the box. All classes, methods, and event types are fully typed.

```typescript
import type {
  ITransactionOutput,
  IUtxoEntry,
  RpcClient,
} from 'kaspa-wasm';

// Type-safe transaction output
const output: ITransactionOutput = {
  address: "kaspa:qr35ennsep3hxfe7lnz5ee7j5jgmkjswsn35ennsep3hxfe7lkaspadev",
  amount: 100000000n, // 1 KAS in sompi (BigInt)
};
```

## Error Handling

```typescript
try {
  await rpc.connect();
} catch (error) {
  if (error.message.includes("WebSocket")) {
    console.error("Connection failed. Check that the node is running.");
  }
}

try {
  const { transactions } = await createTransactions({
    entries: context,
    outputs: [{ address: recipient, amount: amountInSompi }],
    changeAddress: senderAddress,
  });
} catch (error) {
  if (error.message.includes("Insufficient funds")) {
    console.error("Not enough KAS to complete this transaction.");
  } else if (error.message.includes("UTXO")) {
    console.error("UTXO error — try again after syncing.");
  }
}
```

## Browser Considerations

When using the WASM SDK in a browser:

- **WASM file size** — The WASM binary is several megabytes. Use code splitting and lazy loading to avoid blocking initial page load.
- **Memory** — WASM operates within the browser's memory limits. Monitor memory usage when tracking many addresses.
- **Cross-origin** — WebSocket connections to Kaspa nodes must comply with browser CORS policies. Public nodes are configured to accept browser connections.
- **HTTPS** — If your site is served over HTTPS, WebSocket connections must use `wss://` (secure WebSocket). Mixed content will be blocked by the browser.

```typescript
// Example: Lazy-loading the WASM SDK in a React application
async function initKaspa() {
  const kaspa = await import('kaspa-wasm');
  await kaspa.default(); // Initialize WASM
  return kaspa;
}

// Use in a component
useEffect(() => {
  initKaspa().then((kaspa) => {
    // SDK is ready
  });
}, []);
```

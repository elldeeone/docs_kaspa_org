## What is a KIP?

A **Kaspa Improvement Proposal (KIP)** is a formal document that describes a proposed change to the Kaspa protocol, its processes, or its ecosystem tooling. KIPs are the primary mechanism through which the Kaspa community discusses, evaluates, and coordinates protocol upgrades. The process is inspired by Bitcoin's BIP system and Ethereum's EIP system, adapted for Kaspa's governance model.

In current project practice, significant protocol changes are typically documented through the KIP process before implementation.

<Callout>
KIPs exist to ensure that protocol changes are thoroughly discussed, reviewed, and documented before being implemented. They provide a permanent record of the rationale behind design decisions and allow the broader community to participate in Kaspa's evolution.
</Callout>

## Repository Status Model

The canonical KIPs index tracks proposal state via status labels. Current labels in the repository are:

- `Draft`
- `Proposed`
- `Active`
- `Implemented`
- `Rejected`

Use the index and each KIP file header as the source of truth for current status:
[github.com/kaspanet/kips](https://github.com/kaspanet/kips)

## Types of KIPs

KIPs fall into three categories:

**Protocol KIPs** propose changes to the consensus rules, network protocol, transaction format, or other aspects that affect the operation of Kaspa nodes. These are the most consequential type and always require a hardfork or softfork for activation. Examples include KIP-9 (storage mass), KIP-10 (transaction opcodes), and KIP-14 (Crescendo).

**Informational KIPs** describe design issues, best practices, or general guidelines for the Kaspa ecosystem. They do not propose protocol changes and do not require a fork. They serve as reference documents for developers and users.

**Process KIPs** define or modify the processes and governance structures used by the Kaspa community.

## How to Submit a KIP

1. **Write the proposal.** Follow the structure used in existing KIPs.
2. **Submit a pull request.** Open a PR against the [KIPs repository on GitHub](https://github.com/kaspanet/kips).
3. **Track repository status.** Use the PR and KIP metadata to follow review outcomes and status changes.

## Relationship to Hardforks and Softforks

Protocol KIPs that change consensus rules require a **hardfork** to activate on mainnet. A hardfork means that nodes running older software will not recognize blocks produced under the new rules, so network-wide coordination is essential.

Kaspa's hardfork activation mechanism relies on a **DAA score threshold**: when the network's DAA score reaches a predetermined value, the new consensus rules take effect. This provides a deterministic activation point that all upgraded nodes agree on.

<Callout type="warn">
Hardfork activations require all node operators, miners, wallets, and exchanges to upgrade their software before the activation DAA score. Failure to upgrade means a node will fall out of consensus and may follow an invalid chain.
</Callout>

Softforks (backward-compatible rule tightenings) are also possible. In the current public KIPs index, major consensus changes to date have been delivered through hardfork-style activations.

## Notable KIPs

| KIP | Title | Status | Significance |
|---|---|---|---|
| KIP-1 | Rewriting the Kaspa Full-Node in the Rust Programming Language | Implemented | Defines the rationale and plan for rewriting the Kaspa node from Go to Rust |
| KIP-9 | Extended Mass Formula for Mitigating State Bloat | Active | Introduces a mass component that accounts for long-term UTXO storage costs, preventing UTXO bloat attacks |
| KIP-10 | New Transaction Opcodes for Enhanced Script Functionality | Active | Proposes new opcodes for transaction introspection, enabling advanced smart contract functionality |
| KIP-13 | Transient Storage Handling | Active | Refines the mass model to introduce transient mass for the bandwidth dimension of transaction cost |
| KIP-14 | The Crescendo Hardfork | Active | The hardfork that increased block rate from 1 BPS to 10 BPS with all associated parameter changes |

## CLI Flags Reference

kaspad is configured primarily through command-line flags. It also supports an optional configuration file (typically `kaspad.conf` in the data directory) where flags can be specified one per line. Command-line flags override any values set in the configuration file.

### Core Flags

| Flag | Description |
|---|---|
| `--utxoindex` | Enables the UTXO index, required for mining, wallet queries, and any RPC method that looks up UTXOs by address. Increases disk usage. |
| `--archival` | Runs the node in archival mode, retaining all historical block and transaction data instead of pruning. Required for block explorers and analytics services. |
| `--sanity` | Enables additional sanity checks during block validation. Useful for debugging but adds CPU overhead. Not recommended for production. |
| `--yes` | Automatically answers "yes" to any interactive prompts, such as confirmation dialogs during database resets. Useful for scripted or automated deployments. |

### Network Flags

| Flag | Description |
|---|---|
| `--rpclisten` | Sets the gRPC listen address. Default: `127.0.0.1:16110`. Set to `0.0.0.0:16110` to accept remote connections. |
| `--rpclisten-borsh` | Enables and sets the wRPC Borsh listen address. wRPC Borsh is **disabled by default**; you must pass this flag to enable it. Example: `--rpclisten-borsh=0.0.0.0:17110`. |
| `--rpclisten-json` | Enables and sets the wRPC JSON listen address. wRPC JSON is **disabled by default**; you must pass this flag to enable it. Example: `--rpclisten-json=0.0.0.0:18110`. |
| `--rpcmaxclients` | Maximum number of simultaneous RPC client connections. Default: `128`. Increase for high-traffic nodes serving many wallets or applications. |
| `--listen` | Sets the P2P listen address for incoming peer connections. Default: `0.0.0.0:16111`. |
| `--connect` | Connect only to the specified peer(s). Disables automatic peer discovery. Useful for private network topologies. |
| `--addpeer` | Add a persistent peer to connect to in addition to discovered peers. |
| `--outpeers` | Target number of outbound peer connections. Default varies by network. |
| `--maxinpeers` | Maximum number of inbound peer connections to accept. |
| `--disable-upnp` | Disables UPnP port mapping. By default, kaspad attempts to use UPnP to automatically configure port forwarding on your router. Disable this on servers or in environments where UPnP is not available or not desired. |

### Database Management

| Flag | Description |
|---|---|
| `--reset-db` | Deletes the existing database and starts a fresh sync. Required when switching between networks or when the database is corrupted. Combine with `--yes` to skip the confirmation prompt in automated deployments. |

### Network Selection

| Flag | Description |
|---|---|
| `--testnet` | Connect to the public test network (testnet). |
| `--simnet` | Run a local simulation network for development. |
| `--devnet` | Connect to the development network. |

<Callout type="info">
Only one network flag can be specified at a time. If no network flag is provided, kaspad connects to mainnet by default.
</Callout>

### Performance and Tuning

| Flag | Description |
|---|---|
| `--ram-scale` | Scales the amount of RAM used by internal caches and data structures. Default is `1.0`. Values greater than 1.0 allocate more RAM for faster sync and processing; values less than 1.0 reduce memory usage at the cost of performance. |
| `--perf-metrics` | Enables periodic logging of performance metrics (CPU, memory, bandwidth). |
| `--perf-metrics-interval-sec` | Sets the interval in seconds between performance metric log entries. Default: `1`. |

<Callout>
On machines with ample RAM (32 GB+), setting `--ram-scale=2.0` or higher can significantly speed up the initial sync. On memory-constrained systems, use `--ram-scale=0.5` to avoid out-of-memory conditions, accepting slower sync performance.
</Callout>

### Logging

| Flag | Description |
|---|---|
| `--loglevel` | Sets the log verbosity level. Options include `off`, `trace`, `debug`, `info`, `warn`, `error`. Default: `info`. |
| `--nologfiles` | Disables writing log output to files. Logs are only printed to stdout/stderr. Useful for containerized deployments where log aggregation is handled externally. |

### Data Directory

| Flag | Description |
|---|---|
| `--appdir` | Overrides the default data directory path. All database files, logs, and peer data are stored under this directory. |

## Data Directory Structure

The kaspad data directory contains the following:

```
kaspa-mainnet/
  datadir2/
    consensus/          # Block and DAG consensus database
    utxoindex/          # UTXO index database (if --utxoindex enabled)
    ...
  logs/                 # Log files (unless --nologfiles is set)
  kaspad.pid            # PID file for the running process
```

The database files use the RocksDB storage engine internally. These files should not be modified manually.

<Callout type="warn">
If you change networks (e.g., from mainnet to testnet), kaspad automatically uses a different subdirectory (`kaspa-testnet` vs `kaspa-mainnet`). Do not attempt to share a data directory between networks.
</Callout>

## RPC Configuration

kaspad exposes up to three RPC interfaces:

| Interface | Default Port (Mainnet) | Default Port (Testnet) | Flag | Enabled by Default |
|---|---|---|---|---|
| gRPC | 16110 | 16210 | `--rpclisten` | Yes (localhost only) |
| wRPC Borsh | 17110 | 17210 | `--rpclisten-borsh` | No |
| wRPC JSON | 18110 | 18210 | `--rpclisten-json` | No |

By default, only the gRPC interface is enabled, listening on `127.0.0.1` (localhost only). The wRPC interfaces (Borsh and JSON) are **disabled by default** and must be explicitly enabled by passing the `--rpclisten-borsh` or `--rpclisten-json` flags. To allow remote connections on any interface, bind to `0.0.0.0` and ensure appropriate firewall rules are in place.

## Example Configurations

```bash
# Minimal relay node
kaspad

# Mining node with remote RPC and wRPC enabled
kaspad --utxoindex --rpclisten=0.0.0.0:16110 --rpclisten-borsh=0.0.0.0:17110

# Development node with verbose logging
kaspad --utxoindex --rpclisten-borsh=0.0.0.0:17110 --loglevel=debug --perf-metrics --perf-metrics-interval-sec=10

# Memory-constrained node
kaspad --ram-scale=0.3 --nologfiles
```

## What Is Testnet

Testnet is a public Kaspa network that mirrors mainnet functionality but uses valueless coins. It allows developers to test applications, wallet integrations, and protocol changes without risking real funds. Testnet coins (tKAS) have no monetary value.

In the current `rusty-kaspa` release line, local `kaspad --testnet` uses **testnet-10**. It mirrors mainnet's 10 BPS operating mode while remaining a separate network with its own DAG and UTXO set.

<Callout type="info">
If you are testing against current mainnet behavior, use `testnet-10`.
</Callout>

## Running a Testnet Node

Start kaspad with the `--testnet` flag:

```bash
kaspad --testnet --utxoindex --rpclisten=0.0.0.0:16210
```

No additional configuration is needed. The node will automatically connect to testnet peers and begin syncing the testnet DAG.

## Testnet Ports

Testnet uses different default ports than mainnet to allow both to run on the same machine:

| Service | Mainnet Port | Testnet Port |
|---|---|---|
| P2P | 16111 | 16211 |
| gRPC | 16110 | 16210 |
| wRPC Borsh | 17110 | 17210 |
| wRPC JSON | 18110 | 18210 |

<Callout>
Because testnet uses separate ports and a separate data directory (`kaspa-testnet-10`), you can run a mainnet and testnet node simultaneously on the same machine without conflicts.
</Callout>

## Testnet Address Prefix

Testnet addresses use the `kaspatest:` prefix instead of mainnet's `kaspa:` prefix. This prevents accidental cross-network transactions. For example:

- **Mainnet**: `kaspa:qr35ennsep3hxfe7lnz5ee7j5jgmkjswss2ba2ydk`
- **Testnet**: `kaspatest:qr35ennsep3hxfe7lnz5ee7j5jgmkjswss2ba2ydk`

Wallet software should automatically detect and use the correct prefix based on the network it is connected to.

## Getting Testnet KAS

`rusty-kaspa` does not define a canonical faucet endpoint. Funding sources are operational and may change over time.

To request testnet coins:

1. Generate a testnet wallet address (using the CLI wallet with `--testnet` or any compatible wallet).
2. Fund that address from another testnet wallet you control, testnet mining rewards, or a community-operated faucet if available.
3. Wait for the funding transaction to appear and confirm on testnet.

<Callout type="warn">
Do not send mainnet KAS to testnet addresses or vice versa. The address prefixes are different precisely to prevent this mistake. Transactions sent to the wrong network are unrecoverable.
</Callout>

## Differences from Mainnet

| Aspect | Mainnet | Testnet |
|---|---|---|
| Address prefix | `kaspa:` | `kaspatest:` |
| Coin value | Real economic value | No value |
| Network stability | Production-grade | May be reset periodically |
| Mining economics | Production economics | Experimental economics (may change) |
| Data directory | `kaspa-mainnet/` | `kaspa-testnet-10/` |

Testnet may be reset (DAG wiped) during major protocol upgrades. Do not rely on testnet data persisting indefinitely.

## When to Use Testnet vs Simnet

- **Testnet** is best for integration testing with realistic network conditions, testing against other participants, and validating behavior in a multi-node environment.
- **Simnet** (simulation network) is best for local unit testing, rapid development iteration, and scenarios where you need full control over block production. See the [Simnet](/docs/node-operations/simnet) page for details.
